## What this proves

Migration milestone **M-A2**: the CPU reaches `milan_csr` and reads `ID='MILN'`
on the actual softcore (not merely a Verilator RTL harness). This is the proven
foundation of the virtual end-to-end tier ([`docs/testing/VIRTUAL_E2E_PLAN.md`](../VIRTUAL_E2E_PLAN.md)
V0 and [`docs/testing/VIRTUAL_E2E_QEMU.md`](../VIRTUAL_E2E_QEMU.md) T1).

## How it was reproduced

`sw/litex/milan_sim.py` builds a LiteX SoC with the **real `milan_datapath`
RTL** attached as an AXI4-Lite CSR slave at `0x9000_0000`, boots the real BIOS
on the NaxRiscv softcore (the historical sim core; board uses VexiiRiscv, but
CSR map + datapath wiring identical — so the M-A2 proof holds), and drives the
simulation through a pty until the `litex>` prompt, then issues:

    mem_read 0x90000000 16

## Raw evidence (from the pty capture, ANSI-stripped)

```
litex> mem_read 0x90000000 16
Memory dump:
0x90000000  4e 4c 49 4d 21 00 01 00 05 7f 40 00 00 00 00 00  NLIM!.....@.....
```

- Bytes `4e 4c 49 4d` on the wire = `NLIM`; as a little-endian 32-bit word =
  `0x4d494c4e` = **'MILN'** — the expected ID magic.
- `21 00 01 00` = the next CSR words (VERSION `0x00010021`-consistent region).
- Driver markers: `BIOS ... console prompt seen → mem_read sent → memory dump
  observed → capture complete`. Exit status of the driver: **0**
  (`prompt_reached=True dump_seen=True`).

## Toolchain / versions used

- Verilator 5.050 (sim backend)
- LiteX venv: `<litex-work>/litex-milan/venv` (python 3.14.6; has migen + litex +
  NaxRiscv netlist data). **Must be activated** (or invoke `$VENV/bin/python`)
  so subprocess `make`/`python3 -m litex...` resolve to the venv, not system
  python 3.14 (which lacks `migen`/`litex`) — that mismatch broke a first
  attempt with `ModuleNotFoundError: No module named 'migen'` and a BIOS build
  `CalledProcessError` at the `crcfbigen` step.
- `JAVA_HOME=/usr/lib/jvm/java-17-openjdk` set on the build path (needed if the
  NaxRiscv netlist must be regenerated via sbt; the cached netlist served here).
- Boot wall time ≈ 91 s to the prompt, dump at ≈ 92 s (sim `sys_clk` 1 MHz).

## Bootstrap detail worth keeping

The BIOS **memtest** at 64 KiB RAM writes to `0x40000000` and clears it; the
`milan_csr` window at `0x90000000` is untouched by boot, so the read after the
prompt is the datapath's own ID, not leftover RAM. This is a clean M-A2 result.
