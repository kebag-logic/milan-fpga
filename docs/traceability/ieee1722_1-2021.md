## STATUS 2026-08-13 — read before any row below

**The ATDECC implementation this file used to map is DELETED.** The ADP
advertiser and parser, the ACMP talker and listener, and the entire AECP/AEM
engine were removed from the tree — no parameter, no fallback, no shadow arm
(USER: *"remove the old code AECP/ACMP/ADP the lwSRP shall be removed as well.
Only use the uCPU code"*). Two different things happened to the two halves, and
the difference is the whole point of this block:

- **ADP and ACMP MOVED.** They are now the `protocol-processor` submodule's,
  reached through [`hdl/milan/KL_pp_shadow.sv`](../../hdl/milan/KL_pp_shadow.sv)
  and instantiated unconditionally by
  [`hdl/milan/milan_datapath.sv`](../../hdl/milan/milan_datapath.sv). The
  processor publishes a class-D wire face the fabric consumes every clock (the
  bind record, the talker declaration, the SRP state) and its TX rides the
  control lane. MAAP stays in this fabric, bridged by
  [`hdl/milan/KL_pp_maap_shim.sv`](../../hdl/milan/KL_pp_maap_shim.sv), and the
  ACMP DA gate is the talker gate: `acmp_declaring_o` asserts only after a MAAP
  `ALLOC_DA` success. Rows in §1 and §2 are therefore graded **OWNED BY THE
  PROTOCOL PROCESSOR**.
- **AECP CAME WITH IT, NARROWLY.** The processor's AECP uCPU answers on the
  processor's solicited TX lane. **This entity answers `READ_DESCRIPTOR`, and
  answers every other AECP command with a conformant `NOT_IMPLEMENTED` echo** —
  correct `message_type`+1, correct length, correct `controller_data_length`,
  `controller_entity_id` and `sequence_id` echoed. So §3a (Clause 9 transport) is
  now largely **IMPLEMENTED**, while §3b and §3c stay **NOT IMPLEMENTED** for
  every command whose *function* is absent: `GET_`/`SET_` of anything,
  `GET_COUNTERS`, the unsolicited notifications, `IDENTIFY`, MVU and persistence.
  A controller can discover this device over ADP, connect it over ACMP, and walk
  its descriptors — but it cannot name it, configure it, read a counter from it
  or make its LED blink. **The echo is a well-formed refusal, never coverage.**
  Two things are worth carrying out of this section rather than looking them up
  later: Milan Δ7 `ACQUIRE_ENTITY` is **not** distinguished from the generic echo
  (the named known gap), and the descriptor tree now lives in DRAM whose image
  **nothing in this repository builds or loads**, so on a stock build enumeration
  answers `BAD_ARGUMENTS` until one is supplied (an invalid image reports a
  configuration count of zero, and that check precedes the locate).

**The evidence lane moved with the RTL.** The `aecp`, `acmp`, `acmp_lstn`,
`adp`, `adp_advertise`, `adp_parser`, `aempatch` and `persist` Verilator suites
are deleted, along with the tsn_fuzz aecp/acmp/adp campaigns and the matching
BDD features. What survives in this repo is
[`tb/verilator/pp_shadow`](../../tb/verilator/pp_shadow) — the only suite that
elaborates the processor into this datapath — plus
[`tb/verilator/adp_tx`](../../tb/verilator/adp_tx) for the surviving TX arbiter.
`pp_shadow` grades integration: presence and the `PP_STAT` tag, the RX
classify → FIFO → serializer → validator path, the classifier's refusal of
non-control traffic, the side port, the class-D face being live rather than
merely present, the MAAP adapter refusing and granting, and a global
accepted-equals-answered invariant. It does **not** grade the field-level laws
the rows below state. Those live in the submodule's own benches
(`protocol-processor/tb/adp_engine`, `acmp_listener`, `acmp_talker`, `pp_top`),
which this repository's gates do not run. A ✅ that used to mean "pinned here"
now means, in §1 and §2, "pinned somewhere this repo does not run" — the rows
say which, every time.

Verdict tokens in the tables below carry that distinction: 🔵 = owned by the
protocol processor (integration graded here, clause law elsewhere), ❌ = not
implemented in this build.

## 3. AECP + AEM (Clause 7 model/commands, Clause 9 transport)

**THE LOCAL AECP PLANE IS GONE; THE PROCESSOR'S AECP uCPU ANSWERS IN ITS PLACE.**
`KL_aecp_top.sv` and its whole plane — ingress, packet validator, common parser, L0
state, timers, accessor, AEM store, the generated descriptor ROM, the AEM dynamic mux,
the 292 KB response builder, the dynamic-map engine, `KL_aem_patch.sv` and
`KL_persist_journal.sv` — were DELETED on 2026-08-13. What replaced them is the
protocol processor's AECP uCPU, and it does answer: its solicited response drives the
processor's TX lane 0 and rides the parent's control lane.

**What it implements is narrow, and the width of §3 has to be read against that.**

- **`READ_DESCRIPTOR` (0x0004) is implemented.** `SUCCESS` carries
  `configuration_index`, the reserved field and the descriptor; `NO_SUCH_DESCRIPTOR` on
  a locate miss; `BAD_ARGUMENTS` on a bad `configuration_index` — the two error paths
  carrying the §7.4.5 4-byte `{descriptor_type, descriptor_index}` stub.
- **`IDENTIFY_NOTIFICATION` (0x0026) arriving as a COMMAND is `BAD_ARGUMENTS`** —
  §7.4.39.2's opcode-specific rule beats §9.3.5.3.3's generic one.
- **Every other opcode, and every other message type (AEM, ADDRESS_ACCESS,
  VENDOR_UNIQUE), gets a conformant `NOT_IMPLEMENTED` echo**: `message_type`+1, correct
  length, correct `controller_data_length`, `controller_entity_id` and `sequence_id`
  echoed verbatim, payload echoed, padded to the 60-octet minimum. Never silence, never
  malformed.
- **Silently refused, by design:** a command whose `target_entity_id` is not ours, and
  any AECP *response* arriving as input. Both are freed and counted, with no reply.

**So §3a — the Clause 9 TRANSPORT rows — largely PASSES now, while §3b and §3c mostly
do not.** That split is the point of this section and it is deliberate: a conformant
`NOT_IMPLEMENTED` echo discharges §9.3.5's duty to *respond*, and discharges nothing
else. **An echo is not an implementation.** No row below is graded as covered merely
because the command now draws a well-formed refusal; where that distinction could be
misread, the row says so in words.

**Known gap, kept visible:** Milan Δ7 `ACQUIRE_ENTITY` (`NOT_SUPPORTED` with
`owner_id` = 0) is **not** distinguished from the generic echo. The microprogram for it
exists in the ucode and nothing dispatches to it.

**The descriptor tree moved to main memory and its supply chain is not built yet.** The
store fetches descriptors from DRAM over a read-only master at a compile-time base — no
base register — and the image must be written there *before* the entity is enabled.
[`avdecc/gen_aem_store.py`](../../avdecc/gen_aem_store.py) and the end-station builder
still emit a descriptor tree, a directory and an overlay map, and the shape gates still
check them, but **no step in this repository converts that into the processor's image or
loads it into DRAM** — the generator for it (`gen_desc_image.py`) lives in the submodule,
and the builder's `aecp_aem_rom.svh` is an orphan of the deleted `KL_aecp_aem_store`. On
a stock build, therefore, the image is absent and **every `READ_DESCRIPTOR` answers
`BAD_ARGUMENTS`** — a clean refusal, not a hang, and one that heals without a reset
the moment an image is loaded. §3b's rows are graded against that reality: the *engine*
serves descriptors, the *build* does not yet supply any.

Each row's Module cell names what is gone or what owns it now; each Verification cell
keeps the historic evidence explicitly labelled, so a ✅ earned against deleted RTL can
never be mistaken for coverage of the shipping build.
