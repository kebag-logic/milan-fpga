## STATUS 2026-08-13 — the control plane this file profiles was replaced

**This repository's own ADP, ACMP, AECP/AEM and lwSRP implementations are
DELETED** — no parameter, no fallback, no shadow arm (USER: *"remove the old code
AECP/ACMP/ADP the lwSRP shall be removed as well. Only use the uCPU code"*). Milan
is a profile over those base protocols, so almost every row below changed owner or
changed verdict:

- **Discovery (§5.6), connection management (§5.5) and SRP (§4.2.7 / §4.3.3) are
  now the `protocol-processor` submodule's**, reached through
  [`hdl/milan/KL_pp_shadow.sv`](../../hdl/milan/KL_pp_shadow.sv) and instantiated
  unconditionally by
  [`hdl/milan/milan_datapath.sv`](../../hdl/milan/milan_datapath.sv). Those rows
  read **🔵 PROCESSOR**: the fabric integration is graded in this repo, the clause
  law is the submodule's own bench, and this repo's gates do not run it.
- **AECP is answered again — by the submodule's AECP uCPU — and exactly one
  command is IMPLEMENTED.** `READ_DESCRIPTOR` (0x0004), with all three status
  paths: `SUCCESS` carrying `configuration_index`, the reserved
  field and the descriptor; `NO_SUCH_DESCRIPTOR` on a locate miss;
  `BAD_ARGUMENTS` on a bad configuration index — both error paths carrying the
  IEEE 1722.1 §7.4.5 4-byte `{descriptor_type, descriptor_index}` stub.
  `IDENTIFY_NOTIFICATION` (0x0026) arriving as a COMMAND is answered
  `BAD_ARGUMENTS`, because §7.4.39.2's opcode-specific rule beats §9.3.5.3.3.
  **Every other opcode and every other message type — AEM, ADDRESS_ACCESS,
  VENDOR_UNIQUE/MVU — gets a conformant `NOT_IMPLEMENTED` echo**: `message_type`
  + 1, correct length, correct `controller_data_length`, `controller_entity_id`
  and `sequence_id` echoed verbatim. A command whose `target_entity_id` is not
  ours, and any AECP *response* arriving as input, are freed, counted and never
  answered.
- **AN ECHO IS A RESPONSE, NOT A FUNCTION.** The echo discharges IEEE 1722.1
  §9.3.5's duty to answer and nothing else. Every ❌ row in §4 below reads ❌
  **because the command's function is absent**, not because the device is silent
  — GET_COUNTERS, the Table 5.22 push, SET_CLOCK_SOURCE, SET_MAX_TRANSIT_TIME,
  the audio-map setters, GET_DYNAMIC_INFO, GET_MILAN_INFO and the whole MVU
  family, ACQUIRE/LOCK, SET/GET_NAME, SET/GET_SAMPLING_RATE,
  SET/GET_STREAM_FORMAT, SET/GET_STREAM_INFO, SET/GET_CONFIGURATION, IDENTIFY
  and saved state are all still missing. A reader must not count a
  `NOT_IMPLEMENTED` reply as coverage of the command it refuses.
- **The descriptor image is NOT SUPPLIED BY THIS REPOSITORY.** The engine fetches
  the entity model out of main memory over a read-only master at a COMPILE-TIME
  base (`PP_DESC_BASE_P` in [`milan_datapath`](../../hdl/milan/milan_datapath.sv),
  derived by the LiteX SoC as the top 1 MiB of `main_ram`; there is no base
  register). The image generator lives in the submodule
  (`protocol-processor/hdl/aecp/desc/gen_desc_image.py`) and **no step in
  `sw/builder/`, `scripts/`, the SoC builder or the boot path turns an
  `endstation_*.yaml` into its JSON or writes the result into DRAM**;
  `sw/builder/endstation_builder.py` still emits `aecp_aem_rom.svh`, which is the
  ROM of the *deleted* fabric store and an orphan. So on a stock build the region
  is unloaded, the header magic (`"AEMI"`, layout version 1, checksum) fails
  first, and **every `READ_DESCRIPTOR` answers `BAD_ARGUMENTS`** — not
  `NO_SUCH_DESCRIPTOR`: an image marked invalid deliberately reports
  `configurations_count` = 0, and the microprogram checks
  `configuration_index < configurations_count` *before* it locates, so every
  index including 0 is refused and the locate is never reached (the §7.4.5
  4-byte stub still rides the response). The two error statuses therefore
  discriminate the two failures: `BAD_ARGUMENTS` to every read = the image was
  never loaded or is corrupt; `NO_SUCH_DESCRIPTOR` = the image *is* loaded and
  that descriptor is genuinely absent from the model. The store
  never hangs on a missing image (a 4096-cycle watchdog abandons a stalled burst)
  and a late load heals without a reset, so this is a missing build step, not a
  design fault — but until someone writes that step, enumeration is *reachable*,
  not *working*.
- **Milan Δ7 `ACQUIRE_ENTITY` is NOT distinguished from the generic echo.** Δ7
  asks for `NOT_SUPPORTED` with `owner_id` = 0; the microprogram for it EXISTS in
  the processor's ucode (`E_ACQ`) and **nothing dispatches to it**, so opcode
  0x0000 falls into the `NOT_IMPLEMENTED` echo with the rest. That is a wiring
  gap, stated as one.

What that costs against Milan specifically, stated once here so no row below has
to bury it:

- **§5.3.8.2's non-volatile bound state is unimplemented.** The persistence
  journal is deleted and the processor's NVM face is answered by a blank-flash
  responder, so a restore walk always finds blank flash and completes with zero
  records. **Nothing restores a binding across a power cycle.**
- **§7.2.2 / §7.5.2 media-clock SELECTION is unimplemented.** SET_CLOCK_SOURCE is
  not implemented — it draws the `NOT_IMPLEMENTED` echo like every other setter —
  and it was the only writer of the live CLOCK_DOMAIN `clock_source_index`, so it
  is pinned at 0 (INTERNAL) for the life of the build. `KL_crf_rx` still
  validates, measures and counts the CRF Media Clock Input; the MMCM-DRP servo and
  the packet-grid NCO are structurally off and `A_MCSRV_STAT` 0x8F8 reads its
  idle. The actuator that closed roadmap item 6 is still in the tree and can never
  be armed.
- **§5.3.7.6's presentation-time offset is pinned at the Milan 2 ms default** on
  every Stream Output: SET_MAX_TRANSIT_TIME is not implemented. A default, not a
  zero.
- **Table 5.4's per-Stream-Output counters are not counted at all**:
  `KL_talker_diag_ctx` is no longer instantiated, because GET_COUNTERS — its only
  reader — is not implemented. The Table 5.6 Stream Input counters are UNAFFECTED
  and stay readable through the 0x6B8 `A_STRMW_CNT` CSR window.
- **§5.4.5's unsolicited notifications do not exist.** The processor's
  *solicited* AECP TX lane is driven and reaches the wire; the **unsolicited lane
  has no producer at all**, so no Table 5.22 push of any class leaves this device.

### Retained Stream Output counter evidence

The 2026-07-30 silicon window measured Stream Output `FRAMES_TX` advancing at
1.0/s while the peer Stream Input `FRAMES_RX` advanced at 7,995.7/s over a
26.1-second window. The Stream Output result is the conformant observation-
interval reading, not a frame-rate defect. Milan Table 5.4 increments once at
the end of each observation interval that transmitted at least one Stream Data
AVTPDU. The similarly named optional AVB_INTERFACE counter is a since-boot frame
total, so the descriptor type must be checked before interpreting the rate.

The interval-boundary regression is also retained. An event coincident with the
interval tick belongs to the interval that the tick closes. Before the harvest
fix, tick phases 64 and 128 at `TICK_CYC_P = 64` lost a lone transmitted PDU
from both intervals, leaving both `FRAMES_TX` and `TIMESTAMP_UNCERTAIN` at zero.
The current engine folds the boundary event into the closing interval. The
`MEDIA_RESET` source is the `mr` level carried by the transmitted PDU, not the
old tied-low event port. This backs mask bit 2 with observed wire state.

**tsn_gen status:** Milan rides the base-standard models, and the substitution changed
what running them means. The ADP yaml still has an engine to talk to (the processor's);
the AECP yamls have one too, now that the uCPU has landed, and what they measure splits
in two: `aecp_read_descriptor` is a real byte-exact test **once a descriptor image is in
DRAM** — against a stock build it measures `BAD_ARGUMENTS` (the configuration range
check precedes the locate and an invalid image reports a count of zero), which is the
image gap, not the engine — while every other AECP yaml measures the `NOT_IMPLEMENTED` echo's header
discipline (`message_type` + 1, length, `controller_data_length`, echoed
`controller_entity_id` / `sequence_id`). That is worth running as the conformance floor
and must never be read as command coverage. Gaps inherited from the base families are unchanged and matter MORE now that the
hand-built C++ frames are gone: ❌ ACMP model (all M-ACMP rows), ❌ MRPDU models
(M-DEV-5..9), ❌ CRF model (M-CLK-1), ❌ MVU-specific payload models. Against the
processor, a generated corpus fired at the wire is the only mechanised control-plane
coverage this repository could build without writing a bench first.
