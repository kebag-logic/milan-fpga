# Protocol Traceability Map

This map ties every protocol-facing RTL element to the clause that governs it, the
testbench that pins it, and its current verification status: element → governing
clause(s) (Milan v1.2, IEEE 1722-2016, IEEE 1722.1-2021, IEEE 802.1Q-2018,
IEEE 802.1AS-2020, IEEE 1588-2019) → testbench → status.

Generation method: a multi-agent clause-mapping pass over the RTL and the standards
PDFs produced 153 rows and 29 candidate divergence findings; an adversarial
refutation review then attacked the candidates (spec quote in context, RTL
re-derivation, downstream-compensation search, duplicate check against open tasks).
The review budget covered 12 candidates: all 12 were confirmed, none were refuted;
the remaining 17 are carried as `suspect`. Snapshot date: 2026-08-08.

Reconciled 2026-08-08 against the conformance landings VERSION 0x0031-0x0037: a row
a landing closes carries that VERSION id in its status cell, and every finding that
survived review or triage now carries its gh issue number (#54-#65). Still-open
items keep their issue references; landings that await the t534 flash say so.

Status legend:

| Status | Meaning |
|---|---|
| `verified-conformant` | Clause located and read in context; RTL and testbench agree with it. |
| `known-divergence` | Confirmed difference from the letter of the clause; tracked by task number or a documented deviation record. |
| `suspect` | Candidate divergence raised by the mapping pass; not yet through refutation review (review capped at 12 findings). |
| `unverified` | No testbench pins the row, or the function lives outside this repo. |
| `doc-not-on-box` | The governing standard document is not available locally; citations come from RTL banners and were not re-verified. |

**Conventions.** Every RTL, testbench and document reference below is a clickable
relative link. The visible text stays the repo-relative `file:line` span the row
cites; the link target carries the matching line anchor, so following one lands on
the code the row is about rather than at the top of a 5000-line file. A citation
naming several spans anchors on the first. **Line anchors are accurate as of the
snapshot date above and drift as the RTL moves** — the file half of a reference is
durable, the line half is perishable, so treat a landing that looks off by a few
hundred lines as doc-rot rather than as a claim about the code. Test ids like
`es-4.5` refer to the internal COMPLIANCE suite; `tb/verilator/*` and
`tests/features/*` live in this repo. Standards citations (Milan 5.4.2.7,
IEEE 1722-2016 4.4.4.3, table numbers) name no repo object and stay plain text.

Divergences under review:

- The 60-byte final-keep-0x0F MRPDU registration miss was root-caused off the walker: the lwSRP RX tap (like the ACMP and AECP taps) samples tvalid without tready, so a beat parked under DMA backpressure is consumed repeatedly and frames tear or duplicate — the walker itself is clean; fix = qualify on the full handshake per the MAAP pattern (gh #65; supersedes the gaps-doc §0-bis min-size/keep reading).
- The talker FQTSS architecture has no per-stream CBS queues and ships with per-queue CBS disabled, against the letter of Milan 4.3.4 and 802.1Q-2018 34.6.1; the lwSRP bandwidth gate is the deliberate admission regime (gh #63 I6 memo, deviation-with-rationale; traceability M-DEV-11).
- The talker-attribute declaration policy: TalkerAdvertise is declared from boot whenever the CSR bit is set, without gating on Milan 4.3.3.1's Stream-Destination-MAC validity condition (probe within 15 s or matching Listener registration) — a deliberate always-declare design, now tracked (gh #63 I2).
- The SRP Domain check: on a class-A Domain mismatch the RTL only latches a boundary flag and keeps declaring the CSR-fixed {6,3,vid} Domain, where Milan 4.2.7.2.1 requires adopting the received FirstValue and declaring a matching Domain (gh #63 I4).
- Transmission selection: the CBS "transmit" term is the 8-byte-per-cycle AXIS beat acceptance into the MAC FIFO rather than the frame's wire-time occupation, giving measured over-delivery of 9.6% at idleSlope 100 Mb/s and 20.5% at 200 Mb/s against 802.1Q-2018 8.6.8.2 — latent while every shipping queue runs cbs_shaped=0, live the moment per-queue CBS is enabled (gh #63 I5).

Divergences under review:

- The talker-side event-only push law deliberately narrows Table 5.22's "sent when one of the counters is updated" to state-change events, so a healthy FRAMES_TX-only interval close never pushes (task #21).
- The RX-side event-only push law mirrors that narrowing, but the M_PDEC_S accept path still arms dirty on every accepted stream-0 PDU because TV/TNV are per-PDU counters, keeping the sink-0 push at 1 per second while streaming (task #21).
- FRAMES_RX commits the interval's frame total instead of Table 5.6's +1-per-interval (project ruling 2026-08-05, defensible under the implementation-specific interval), leaving TX and RX asymmetric against identical clause wording (task #21).
- The AVB_INTERFACE unsolicited GET_COUNTERS push has no 1-second-per-descriptor limiter, so a link flapping or GM churning faster than 1 Hz would violate Table 5.22's rate restriction (gh #60).
- No unsolicited GET_COUNTERS notification can ever be generated for STREAM_INPUT descriptors other than index 0, nor for the CRF Media Clock Input — those descriptors update their counters silently (gh #60).
- When CRF is the active clock source, the unsolicited STREAM_INPUT[0] GET_COUNTERS payload carries the CRF engine's lock tallies as sink-0 MEDIA_LOCKED/MEDIA_UNLOCKED, disagreeing with the solicited response for the same index (gh #60).
- The CRF sink's counters are backed by 8-bit saturating and 16-bit wrapping registers where Milan 5.3.8.10 mandates 32-bit wrapping counters (gh #61).
