# Protocol Traceability Map

This map ties every protocol-facing RTL element to the clause that governs it, the
testbench that pins it, and its current verification status: element → governing
clause(s) (Milan v1.2, IEEE 1722-2016, IEEE 1722.1-2021, IEEE 802.1Q-2018,
IEEE 802.1AS-2020, IEEE 1588-2019) → testbench → status.

## The control plane under this map changed on 2026-08-13 — read this first

**This repository's own IEEE 1722.1 / SRP control plane is DELETED.** The ADP
advertiser and parser, the ACMP talker and listener, the entire AECP/AEM engine
(ingress, validator, parser, L0 state, timers, accessor, AEM store, the generated
descriptor ROM, the dynamic-map engine, the response builder, the AEM patch port
and the persistence journal) and the whole lwSRP applicant/registrar/walker stack
are gone from the tree. There is no parameter, no fallback and no shadow arm
(USER, explicit and repeated: *"remove the old code AECP/ACMP/ADP the lwSRP shall
be removed as well. Only use the uCPU code"*; *"do not leave the option, remove
everything out of the code base that is legacy"*). Git history keeps every line;
this map describes the build, not the history.

**ADP, ACMP and SRP are now owned by the protocol processor.**
[hdl/milan/KL_pp_shadow.sv](../../hdl/milan/KL_pp_shadow.sv) wraps the pinned
`protocol-processor` submodule (architecture of record v2.0) and
[hdl/milan/milan_datapath.sv](../../hdl/milan/milan_datapath.sv) instantiates it
**unconditionally**. Its class-D wire face republishes everything the processor
knows as levels the fabric consumes every clock — the per-sink bind record, the
per-source talker declaration, the SRP reservation, granted slope and adopted
Domain — and its packed TX rides the control lane. MAAP stays in this fabric
(`KL_maap`, because the processor implements no MAAP by design) with
[hdl/milan/KL_pp_maap_shim.sv](../../hdl/milan/KL_pp_maap_shim.sv) bridging the
two allocation models. The ACMP **DA gate is the talker gate**:
`acmp_declaring_o` asserts only after a MAAP `ALLOC_DA` success, so AAF admission
is still "a destination address exists AND the source is declaring".

**This entity serves the processor's declared AECP command inventory, including
`READ_DESCRIPTOR` and `GET_COUNTERS`.** Unsupported commands receive the
conformant fallback. The processor's AECP uCPU has landed
and its solicited response drives the processor's TX lane 0 onto the parent's
control lane. So this device DISCOVERS over ADP, CONNECTS over ACMP, RESERVES
over SRP — and is reachable on AECP, narrowly. `READ_DESCRIPTOR` (0x0004) is
implemented for real (`SUCCESS` with `configuration_index`, the reserved field
and the descriptor; `NO_SUCH_DESCRIPTOR` on a locate miss; `BAD_ARGUMENTS` on a
bad configuration index, both errors carrying the §7.4.5 4-byte
`{descriptor_type, descriptor_index}` stub); `IDENTIFY_NOTIFICATION` (0x0026)
sent as a *command* is `BAD_ARGUMENTS` per §7.4.39.2; a command for another
`target_entity_id` and any AECP *response* arriving as input are freed, counted
and left unanswered by design.

**Everything else is still unimplemented, and the echo does not change that.** A
well-formed refusal discharges §9.3.5's duty to respond and discharges nothing
else. The VERSION `0x0002_0055` exceptions are `GET_AVB_INFO` and the bounded
`GET_AS_PATH` response described in §5. Each of the following is otherwise a row
below still graded `not-implemented`, and none of them is coming back on a
schedule this map knows about:

- ACQUIRE_ENTITY / LOCK_ENTITY and every entity-lock rule built on them —
  including the named known gap: **Milan Δ7's `NOT_SUPPORTED` with `owner_id` = 0
  is not distinguished from the generic echo**
- SET/GET_CONFIGURATION, SET/GET_NAME, SET/GET_SAMPLING_RATE
- SET/GET_STREAM_FORMAT, SET/GET_STREAM_INFO, SET/GET_MAX_TRANSIT_TIME
- GET_AUDIO_MAP / ADD_AUDIO_MAPPINGS / REMOVE_AUDIO_MAPPINGS
- GET_COUNTERS on every descriptor, **and the Milan Table 5.22 unsolicited push**
- GET_MILAN_INFO and the rest of the MVU set not named above
- REGISTER/DEREGISTER_UNSOLICITED_NOTIFICATION and the departing-controller engine
- IDENTIFY (`o_identify` is tied 0 — the LED is structurally dark)
- SET_CLOCK_SOURCE
- saved-state persistence — **nothing restores a binding across a power cycle**

Three of those are function rather than paperwork and get their own sentence:

1. **The CRF media clock can never be SELECTED.** `SET_CLOCK_SOURCE` was the only
   writer of the live CLOCK_DOMAIN `clock_source_index`, so it is pinned at 0 —
   the INTERNAL media clock — for the life of the build. `KL_mmcm_drp_servo` and
   the `KL_media_nco` packet-grid servo are therefore **structurally off** and
   `A_MCSRV_STAT` (0x8F8) reads its idle. The CRF Media Clock Input engine still
   parses, counts and reports; it simply cannot steer anything.
2. **Presentation-time offset is pinned at the Milan 2 ms default** on every
   Stream Output, `SET_MAX_TRANSIT_TIME` being gone. That is a DEFAULT, not a
   zero: 0 ns would be a presentation time in the past and every listener would
   drop every frame as late.
3. **The Milan Table 5.4 per-STREAM_OUTPUT diagnostic counters are live for
   solicited reads.** `KL_talker_diag_ctx` is instantiated per declared output
   and GET_COUNTERS serves the compact five-counter layout. The Table 5.22
   unsolicited producer remains open. STREAM_INPUT counters remain live.

This is a stated capability boundary, taken by the user with the price in front
of him. It is not a regression under repair, and no row below is written as
though the command were about to return.

**Where the descriptors come from, and why enumeration can still read empty.**
The AEM tree is no longer a fabric ROM. The processor's descriptor store fetches
it from main memory over a **read-only** master at a **compile-time base** —
surfaced by `milan_datapath` as `o_desc_mem_*`/`i_desc_mem_*`, bridged to DRAM by
the LiteX SoC, which *derives* the base from the `main_ram` region rather than
mirroring a literal. There is no base register: software's only lever is to write
the image at that base **before the entity is enabled**. A region that fails the
image header's magic, version or checksum reads as "image not loaded", and every
`READ_DESCRIPTOR` then answers `BAD_ARGUMENTS` (an invalid image reports a
configuration count of zero, and the `configuration_index` check precedes the
locate) — a clean refusal, never a
hang, because the store's watchdog abandons a stalled burst; a late load heals
without a reset, since each locate against an invalid image re-arms the header
probe. The live supply path is an **explicit deployment ownership transfer**:
`endstation_builder.py --write-fragment` or `--write-rtl` generates
`aem_desc.bin`, its paired `aem_desc.json` manifest, `aem_desc.map`, and the
loader payload in the sibling rootfs overlay. The tracked `S50milan` stage runs
`aemi-load` before identity programming and entity enable; the loader validates
the manifest/window pairing, AEMI magic and firmware version, then verifies the
DRAM readback. An ordinary builder inspection does not mutate the deployment
overlay, and a custom flow that skips this handoff still fails closed with
`BAD_ARGUMENTS`; a later valid load heals without reset. The two response codes
therefore discriminate: `BAD_ARGUMENTS` everywhere means no valid image, while
`NO_SUCH_DESCRIPTOR` means the image is loaded and that descriptor is genuinely
absent from it. [ENDSTATION_BUILDER.md](../ENDSTATION_BUILDER.md) owns the current
generation and boot contract.

**The evidence lane moved with the RTL.** Thirteen Verilator suites went with it
(`aecp`, `aempatch`, `acmp`, `acmp_lstn`, `persist`, `adp`, `adp_advertise`,
`adp_parser`, `lwsrp`, `lwsrp_ctx`, `lwsrp_rx`, `lwsrp_tx`, `lwsrp_switchpdu`),
along with the tsn_fuzz aecp/acmp/adp campaigns — only the AAF campaign survives
— and roughly 33 BDD feature files. The surviving in-repo control-plane suite is
[tb/verilator/pp_shadow](../../tb/verilator/pp_shadow), the only one that
elaborates the submodule into this datapath: it grades presence and the
`PP_STAT` tag, the RX classify → FIFO → serializer → validator path, the
classifier's refusal of non-control traffic, the side port answering with the
processor's own magic, the class-D face being **live** rather than merely
present, and the MAAP adapter in both its refusing and its granting form, under
a global accepted-equals-answered anti-wedge invariant. What it does **not** do
is pin the clause-by-clause field laws the deleted suites pinned. Those live in
the submodule's own benches (`protocol-processor/tb/adp_engine`,
`acmp_listener`, `acmp_talker`, `srp_top`, `srp_decoder`, `srp_encoder`,
`srp_stream_fsms`, `pp_top`) and **this repository's gates do not run them** —
`scripts/lint_rtl.py` reads the submodule as sources only. Every row below says
which of the two it rests on, and a row that rests on neither says so.

Firmware VERSION major is now **2** (`0x0002_0055`): a block redesign bumps the
major, and replacing the entire control plane is the largest one this tree has
had.

## How this map was built, and what the re-grade did to it

Generation method: a multi-agent clause-mapping pass over the RTL and the standards
PDFs produced 153 rows and 29 candidate divergence findings; an adversarial
refutation review then attacked the candidates (spec quote in context, RTL
re-derivation, downstream-compensation search, duplicate check against open tasks).
The review budget covered 12 candidates: all 12 were confirmed, none were refuted;
the remaining 17 were carried as `suspect` and later triaged into the gh issue set.
Snapshot date: 2026-08-08, reconciled 2026-08-09 against the landings VERSION
0x0031 through 0x0040.

Re-graded 2026-08-13 against the substitution. A row whose implementation was the
deleted RTL now reads `owned-by-processor` where the function really moved (ADP,
ACMP, SRP) and `not-implemented` where it really went away (everything AECP). The
landing history in the surviving rows is kept deliberately — a VERSION id in a
status cell records when a law landed in the plane that then owned it, and the
`Confirmed findings` section at the end is retained as the review's audit trail
even though the RTL it names is gone. Neither is a claim about today's wire. Where
a row was closed against RTL that has since been deleted, the row says so instead
of quietly inheriting the green.

Status legend:

| Status | Meaning |
|---|---|
| `verified-conformant` | Clause located and read in context; RTL and testbench agree with it. |
| `owned-by-processor` | The behaviour moved into the `protocol-processor` submodule behind `KL_pp_shadow`. The fabric integration is graded here; the field-level clause law is the submodule's own bench, which this repo's gates do not run. Never read this token as "verified in this repository". |
| `not-implemented` | This build does not implement the clause at all. Not "untested", not "degraded" — absent, with the CSR words that fed it reading structural zeros. |
| `known-divergence` | Confirmed difference from the letter of the clause; tracked by task number or a documented deviation record. |
| `superseded` | The finding or deviation described RTL that no longer exists. The old verdict is not carried forward, and no new verdict is claimed without evidence. |
| `unverified` | No testbench pins the row, or the function lives outside this repo. |
| `doc-not-on-box` | The governing standard document is not available locally; citations come from RTL banners and were not re-verified. |

**Conventions.** RTL, testbench and document references are relative links. Line
anchors drift as the RTL moves, and the 2026-08-13 deletion moved most of it: the
anchors that pointed into the old control-plane files are gone with their files,
and anchors into `milan_datapath.sv` were dropped rather than re-guessed, because
a plausible-looking wrong line is worse doc-rot than no line at all. The file half
of a reference is durable; treat any surviving line half as perishable. Test ids
like `es-4.5` refer to the internal COMPLIANCE suite; `tb/verilator/*` and
`tests/features/*` live in this repo. Standards citations (Milan 5.4.2.7,
IEEE 1722-2016 4.4.4.3, table numbers) name no repo object and stay plain text.

## 2. AECP + AEM — processor command surface

**This device answers the processor's declared command inventory, including
`READ_DESCRIPTOR`, VERSION `0x0002_0055` `GET_AVB_INFO`, and the bounded
`GET_AS_PATH`; it refuses unsupported commands in the correct form.** The local
AECP plane is deleted; the processor's AECP uCPU replaced it. A command arrives
at the wrapper's classifier, is admitted as EtherType 0x22F0 control traffic,
reaches the processor's validator, and is dispatched to the engine, which either
serves a supported command or emits a conformant `NOT_IMPLEMENTED` echo —
`message_type`+1, correct length, correct
`controller_data_length`, `controller_entity_id` and `sequence_id` echoed
verbatim, payload echoed, padded to the 60-octet Ethernet minimum. It is never
silence and never malformed.

**Read the Status column with that split in mind.** `implemented` in this section
means the *function* is served. A row that says `not-implemented` is still
answered on the wire — with a refusal — and that refusal is deliberately not
counted as coverage anywhere below. Where the distinction could be misread, the
row says so.

The rows are kept in full rather than deleted. A traceability matrix that drops
the clauses it no longer meets is not a shorter matrix, it is a false one; and
these clauses are exactly the ones a controller, a compliance run or the next
engineer will ask about first. Each row names what owns it now or what is gone,
what CSR words its removal turned into structural zeros, and the clause that
still goes unmet.

## 4. SRP / IEEE 802.1Q

The clause splits cleanly in two now. **Reservation** — MSRP, MVRP, the MRP
applicant and registrar, Domain adoption, the admission arithmetic — moved into
the protocol processor with ADP and ACMP; the whole lwSRP stack that used to sit
beside the shaper under `hdl/ieee8021q/` is deleted — applicant, registrar,
context table, walker, timers and bandwidth gate. **Shaping** —
tag decode, priority regeneration, per-class queues, the credit-based shaper and
transmission selection — is fabric, lives on under `hdl/ieee8021q/ts/`, and is
unchanged by the substitution. The seam between them is the class-D face: the
processor publishes `srp_sr_admitted_o`, `srp_sum_slope_bps_o` and the adopted
{priority, VID} pair as levels, and [hdl/milan/milan_datapath.sv](../../hdl/milan/milan_datapath.sv)
feeds them straight into the streaming licence, the CBS idleSlope mux and every
C-TAG this device emits.

Divergences, and where each now stands:

- The talker FQTSS architecture still has no per-stream CBS queues and still ships with per-queue CBS disabled, against the letter of Milan 4.3.4 and 802.1Q-2018 34.6.1; admission is the reservation regime, which is now the processor's `KL_srp_admission` rather than the deleted bandwidth gate. This remains a **recorded deviation with rationale** (gh #63 I6 memo; traceability M-DEV-11), and the substitution neither closed it nor widened it.
- The slope-versus-gate ordering invariant survives the substitution on both edges (equal on the opening edge, conservative on the closing one), but it stopped being a *testable* behaviour: no bench in this repo can point at it any more. That is a real loss of evidence, recorded here rather than absorbed.
- SUPERSEDED. The 2026-08 SRP round (gh #63 I2/I3/I4, gh #65, VERSION 0x0032 to 0x0040) closed the 4.3.3.1 declaration gate, the registrar's In-law, Domain adoption, and the tvalid-without-tready monitor-tap defect that duplicated and tore frames. All four landed in lwSRP modules that are deleted. The tap-discipline lesson is the one that carried forward by construction: `KL_pp_shadow` qualifies its RX tap on `tvalid && tready`, and its banner names the gh #65 hazard as the reason.
- Two gaps recorded against the old applicant are moot in the same way as the AECP ones: the TalkerAdvertise PriorityAndRank octet and the withdraw-LV pair both named registers in the deleted serializer. Whether the processor's encoder carries the operational pair in those fields is UNVERIFIED here.
- The MRPDU counters at 0x680 are structural zeros, so the "is the applicant talking?" question that those counters used to answer now needs a wire tap. The Domain word, the granted slope and the over-limit bit still answer "did the network accept us?".
