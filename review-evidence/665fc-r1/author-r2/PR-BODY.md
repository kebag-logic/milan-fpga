## Description

The mailbox ingress filter now classifies each frame on its full tuple, then
its identity term, as REQUIREMENTS.md section 1 tabulates. The contract,
its generated outputs, the RTL, the host model, the firmware's set-up and the
suite move together, with a planted defect per rule.

| Piece | Change |
|---|---|
| Contract (`sw/mailbox/mailbox.yaml`, major 2) | Each channel matches up to two tuples (destination MAC, EtherType, subtype where named). The destination is a fixed address with its clause (Table B.1, Table B.10, 802.1Q 35.2.2.1, 11.2.3.1.3) or `own`, the arrival interface's MAC. ACMP takes own unicast as the owner's tolerance; AECP takes own unicast only. MSRP and MVRP are each paired with their own address. AECP adds the response term (controller_entity_id, byte 26, odd message types; Table 9-1) beside the command term (target_entity_id, even). `OWN_MAC_LO/HI` per interface at `0x080 + 8 * i`, in register space nothing used; `FILTER_MISMATCH` at `0x074`. No tuple may name an 802.1Q TPID. Narrowing the filter raises major: a major-1 firmware would never write the own MAC AECP now needs. |
| Generator (`sw/mailbox/*.py`) | Models, emits (tuple tables, reference page), cross-checks the new block and refuses a TPID tuple, a tuple with no destination, an own-MAC block that spills or collides, and (round 2) message types with no subtype or wider than four bits. Self-test: 16 output arms, 15 contract arms, a two-interface variant clean, a four-interface one refused. `--variant-interfaces N --out DIR` writes a variant into a build directory only. Outputs regenerated by `--write`. |
| RTL (`KL_mbx_rx.sv`; `KL_mbx.sv` generated) | Full-tuple classification against the arrival interface's own MAC (at byte 14 in round 1, at byte 15 since round 2). An untagged frame whose EtherType a tuple names, matching no tuple, counts once in `FILTER_MISMATCH` and sets `IRQ_STATUS.ERR`. Identity refusals, closed channels, tagged and short frames never count. Tagged frames reach nothing by construction: the key is wire bytes 12-13, where the TPID sits. Token buckets unchanged. `KL_mbx`'s ports unchanged. |
| Host model (`sw/firmware/ctrl/host/mbx_model.c`) | The same rules, answering the same suite. |
| Firmware (`sw/firmware/ctrl`) | `mbx_filter_set_own_mac(interface, mac)`, `mbx_filter_mismatch()`; `ctrl_loop_open()` writes every interface's own MAC before any channel opens; the app gives the entity's MAC (the one ADP sends) to every interface. |
| Tests (round 1) | Suite groups Q0 to Q10: a positive control per table row; tag, destination, EtherType, subtype and identity changed one at a time per row; untagged AAF/CRF; CONTROLLER_AVAILABLE response delivered, one for another controller dropped, every message type both ways; own MAC per interface index; FILTER_MISMATCH once and never otherwise; buckets apart from the filter. `make run-if2` runs it all on two interfaces, on the RTL and the model. New unit tests D11, D12, U4 and an L1 addition. 21 RTL and 17 model or firmware defects. |
| Docs | `MAILBOX_SPLIT.md` (the filter as implemented, verification, area), the suite, ctrl and gtest READMEs. |
| Round 2: the MAAP DEFEND | A match tuple may name AVTP message types (`msg_types`). The `maap` row is now (destination `91:E0:F0:00:FF:00`) OR (own unicast AND message_type DEFEND), then the unchanged range term (B.2.1: PROBE and ANNOUNCE go to the multicast address, DEFEND to the triggering PROBE's source MAC). `KL_mbx_rx` decides the channel at byte 15, the message_type byte, or at the last byte of a frame ending at 14 (message_type 0, so every other tuple classifies as before); the four-word queue holds bytes 0 to 15, so nothing waits. ## Known limitations / out of scope

- F2 to F5 behaviour and the datapath tap: the SoC still holds the mailbox's ingress idle.
- The amended MAAP row (REQUIREMENTS.md section 1, NFR-SCOUT-08, H-MAAP)
  needs the owner's approval before merge (#665 comment 6026839422, item 4).
- The contract stays at version 2.0: major 2 has not left this branch, so
  the wider MAAP row is part of the first major-2 contract rather than a 2.1.
- NFR-SCOUT-02 is not edited. It names the VLAN-tag, destination, EtherType
  and subtype tuple and defers the table to NFR-SCOUT-08; the MAAP own-unicast
  tuple also matches message_type.
- The fabric's `KL_maap` sends DEFEND multicast; that frame still reaches the
  MAAP ring. F2's other notes on `KL_maap` are F2's.
- `FILTER_MISMATCH` saturates at `0xFFFF` like every mailbox counter; like
  theirs, the suite does not drive it to the bound.
- One MAC per entity today: the app gives the entity's MAC to every interface,
  because ADP sends that one MAC on each. The registers and `ctrl_loop_open`
  take one per interface for an entity model that has them (#69).
- `mbx_tb::Bench::reset()` keeps queued ingress bytes, so a group that wedges
  the RTL feeds the next one. This is pre-existing and unchanged here.
