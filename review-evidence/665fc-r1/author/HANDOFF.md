(`021b9c1f`).

## 8. Readings, open items and decisions for the manager

- **Contract major 2.** The narrower filter would silently drop AECP for a
  firmware built against major 1 (it never writes the own MAC), so `mbx_open()`
  must refuse it; the YAML's change rule now says a narrowing raises major.
- **Tagged frames by construction.** The classification key is wire bytes 12
  and 13, where a tag's TPID sits, and the generator refuses a tuple naming one
  of 802.1Q-2018 Table 9-1's TPIDs. There is no separate tag detector to plant a
  defect in, so rule 1's RTL arm makes a TPID match a tuple's EtherType.
- **Control EtherType** is any EtherType some tuple names: `0x22F0`, `0x22EA`,
  `0x88F5`, as REQUIREMENTS.md section 1 lists them.
- **What counts.** A tuple failure counts whatever `FILTER_EN` holds. An identity
  refusal, a closed channel, a tagged frame and a frame that ends before byte
  14 never count. A mismatch sets `IRQ_STATUS.ERR`, which the register's doc
  already promised for "a drop or error counter moved".
- **AECP message types** by parity (Table 9-1: commands even, responses odd;
  the reserved 10 to 13 keep it, as the fabric engine's `msg_type[0]` does).
- **One MAC per entity.** ADP sends the entity's one MAC on every interface, so
  the app gives it to every interface; the per-interface registers and
  `ctrl_loop_open`'s array are ready for an entity model with one per interface
  (#69).
- **Requirement status sentences, not edited** (owner-approved text):
  REQUIREMENTS.md lines 93-94 ("The contract lane after FT implements these
  additions ...; F0's current filter is described ...") and FR_NFR.md line 427
  ("These additions await the contract lane after FT") and line 599 ("Contract
  lane after FT, before F2 to F5"). They become historical when this lands.
- **Harness note, not changed:** `mbx_tb::Bench::reset()` keeps bytes still
  queued on the ingress stream, so a group that wedges the RTL feeds its
  leftovers to the next group (seen only under the replaced arm above).
- **Saturation** of `FILTER_MISMATCH` at `0xFFFF` is implemented like every
  other counter's and, like theirs, not driven to the bound by the suite.
