## Description

The mailbox ingress filter now classifies each frame on its full tuple, then
its identity term, as REQUIREMENTS.md section 1 tabulates. The contract,
its generated outputs, the RTL, the host model, the firmware's set-up and the
suite move together, with a planted defect per rule.

| Piece | Change |
|---|---|
| Contract (`sw/mailbox/mailbox.yaml`, major 2) | Each channel matches up to two tuples (destination MAC, EtherType, subtype where named). The destination is a fixed address with its clause (Table B.1, Table B.10, 802.1Q 35.2.2.1, 11.2.3.1.3) or `own`, the arrival interface's MAC. ACMP takes own unicast as the owner's tolerance; AECP takes own unicast only. MSRP and MVRP are each paired with their own address. AECP adds the response term (controller_entity_id, byte 26, odd message types; Table 9-1) beside the command term (target_entity_id, even). `OWN_MAC_LO/HI` per interface at `0x080 + 8 * i`, in register space nothing used; `FILTER_MISMATCH` at `0x074`. No tuple may name an 802.1Q TPID. Narrowing the filter raises major: a major-1 firmware would never write the own MAC AECP now needs. |
| Generator (`sw/mailbox/*.py`) | Models, emits (tuple tables, reference page), cross-checks the new block and refuses a TPID tuple, a tuple with no destination, an own-MAC block that spills or collides. Self-test: 14 output arms, 12 contract arms, a two-interface variant clean, a four-interface one refused. `--variant-interfaces N --out DIR` writes a variant into a build directory only. Outputs regenerated by `--write`. |
| RTL (`KL_mbx_rx.sv`; `KL_mbx.sv` generated) | Full-tuple classification at byte 14 against the arrival interface's own MAC. An untagged frame whose EtherType a tuple names, matching no tuple, counts once in `FILTER_MISMATCH` and sets `IRQ_STATUS.ERR`. Identity refusals, closed channels, tagged and short frames never count. Tagged frames reach nothing by construction: the key is wire bytes 12-13, where the TPID sits. Token buckets unchanged. `KL_mbx`'s ports unchanged. |
| Host model (`sw/firmware/ctrl/host/mbx_model.c`) | The same rules, answering the same suite. |
| Firmware (`sw/firmware/ctrl`) | `mbx_filter_set_own_mac(interface, mac)`, `mbx_filter_mismatch()`; `ctrl_loop_open()` writes every interface's own MAC before any channel opens; the app gives the entity's MAC (the one ADP sends) to every interface. |
| Tests | Suite groups Q0 to Q10: a positive control per table row; tag, destination, EtherType, subtype and identity changed one at a time per row; untagged AAF/CRF; CONTROLLER_AVAILABLE response delivered, one for another controller dropped, every message type both ways; own MAC per interface index; FILTER_MISMATCH once and never otherwise; buckets apart from the filter. `make run-if2` runs it all on two interfaces, on the RTL and the model. New unit tests D11, D12, U4 and an L1 addition. 21 RTL and 17 model or firmware defects. |
| Docs | `MAILBOX_SPLIT.md` (the filter as implemented, verification, area), the suite, ctrl and gtest READMEs. |

and submodules) found nothing naming the mailbox, and every arm of the

## Known limitations / out of scope

- F2 to F5 behaviour and the datapath tap: the SoC still holds the mailbox's ingress idle.
- REQUIREMENTS.md lines 93-94 and FR_NFR.md lines 427 and 599 say the filter
  awaits "the contract lane after FT". They are owner-approved requirement
  text and are left for the manager; this lane edits no requirement.
- `FILTER_MISMATCH` saturates at `0xFFFF` like every mailbox counter; like
  theirs, the suite does not drive it to the bound.
- One MAC per entity today: the app gives the entity's MAC to every interface,
  because ADP sends that one MAC on each. The registers and `ctrl_loop_open`
  take one per interface for an entity model that has them (#69).
- `mbx_tb::Bench::reset()` keeps queued ingress bytes, so a group that wedges
  the RTL feeds the next one. This is pre-existing and unchanged here.
