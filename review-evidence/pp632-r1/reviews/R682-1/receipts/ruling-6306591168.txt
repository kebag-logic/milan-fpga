**Ruling on R677-2-F1 (the SET_STREAM_INFO change gate)**

The clauses split the three values:
- Milan v1.2 5.4.2.9: the SET sets the Presentation Time offset to the commanded value, and the successful response echoes that value. The stored row is the state the command sets.
- Milan v1.2 5.4.2.10.2: GET_STREAM_INFO's msrp_accumulated_latency is "the presentation time offset currently used by the talker". GET keeps serving the applied (rounded) row, as round 2 made it.
- Milan v1.2 5.4.5.2 and IEEE 1722.1-2021 7.5.2: a notification follows a successful command that modifies the state. The notification carries the response's content (5.4.5.1), which is the commanded value.

The gate therefore compares the commanded value with the **stored** row, like for like, not with GSI word 3. The processor already reads that row for the notification body (`READ_ST RGN_DYN + SEL_PTOFF` in E_SINFOUNS), so the fix is that read in E_SINFO in place of `GATHER_EXT GSI(3)`.

This is a processor change. It goes in a separate processor PR off processor main 08023123, which relates to milan-fpga #632. It is consumed by the fourth pin adoption, and #770 merges after that adoption.

Required in the processor PR:
- the E_SINFO change;
- a processor-level test: an identical SET pushes nothing, and a changed SET pushes once;
- a planted defect that restores the GSI(3) compare and fails that test.

Required in #770:

- Its planted control, restoring the present gate.
- Measure it in your lane against the fixed processor, with the processor change applied uncommitted to the submodule checkout. Record that the case fails at the current pin.
- Scope the "what a controller reads is what every output stamps" claim (`MEDIA_CLOCK_FOLLOWING.md`, `KL_mtt_round.sv` banner) to GET_STREAM_INFO. Document the SET echo against the applied readback, with the non-idempotent write-back, citing 5.4.2.9 and 5.4.2.10.2.
- Out of scope, recorded only: an applied value that changes without a SET, for example at a media rate change. That is the 1722.1-2021 7.5.2 "normal operation" case. Record it as a follow-up in HANDOFF.md; do not implement it.
