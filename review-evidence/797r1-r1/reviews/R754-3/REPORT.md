## Findings

### F1 - MINOR - Conformance, RTL, Robustness, Tests, Docs - `RENDER_STAT` says only index 0 returns the status; any selected listener does

- **Where:** `docs/reference/REGISTER_MAP.md:3974-3975`, generated by `scripts/register_page.py:772` `read_value_table` from the decode at `hdl/common/csr/milan_csr.sv:2445-2451`.
- **Authority:** this round's check 2 and R754-2 F4: each row is one conjunction true as printed, swept on the shipping and a 2x2 build. #797 acceptance: no current document contains a statement the code contradicts. The page's `Build parameters` section limits parameter dependence to "some reset values" (`REGISTER_MAP.md:239`).
- **Evidence:** the RTL loops `s < N_LISTENERS_P` and returns `i_render_status[s*32 +: 32]` when `!strm_dir_r && strm_idx_r == s`.
  - The generator resolves that loop at the shipping value 1, so the page prints "`STRM_SEL[8]` selects a listener and the stream index `STRM_SEL[3:0]` is 0", and "any other case" reads 0.
  - On a 2x2 build, `SEL` `0x001` and `0x201` read `0x70000001`, the driven status of listener 1. The printed row gives 0. That is 16 disagreements in 24,064 reads (`receipts/sweep/compare_2x2.txt`).
  - The other 12 window tables keep the build-general "the selected stream exists", so a reader has no signal that this one row is shipping-only.
  - The same decode applies to the `endstation_arty_4x4` and `endstation_ax7101_8x8` shapes. I did not simulate those.
- **Why the published sweep missed it:** `author-r3/tools/gen_read_table_sim.py` reads 12 addresses. `author-r3/HANDOFF.md:135` gives the reason for leaving out the other five: they "have no `or` to misread". This row has no `or`, and it is still false.
- **Impact:** on a multi-listener build, a programmer who trusts the table reads a live status as impossible and treats listener 1 and above as always 0. The shipping 1x1 build is correct.
- **Required outcome:** the row is true on both builds. Either print a condition that holds at any `N_LISTENERS_P`, or state on the page that the row holds only at the shipping `N_LISTENERS_P` = 1 and name the wider decode. The sweep behind the "0 disagreements" claim covers all 17 tables.
- **Verification:** `tools/run_sweep.sh` gives 0 disagreements on both builds, and `--check` is fresh. Replacing the row with "the selected stream exists and `STRM_SEL[8]` selects a listener" already gives 0 on both logs (`receipts/sweep/compare_proposed_row_ship.txt`, `compare_proposed_row_2x2.txt`).
