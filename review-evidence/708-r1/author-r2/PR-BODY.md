## Known limitations / out of scope

- **Post-merge flash and soak** (#708 acceptance 5) belong to the manager after the merge.
- **The shipping launcher's own build was not completed here.** Its synthesis runs eight parallel Vivado workers, which
  exceed this lane's memory budget, so it was stopped and none of its output is used. The image is the bitstream of the
  route the gate measured, which used one synthesis worker as the recipe does, with the shipping script's
  configuration properties. Dev's own shipping build on the same host gives that flow's reference figure.
- **Dev has moved since the merge.** It is now at `8eacc408`, which adds PR #745 (CI replay memory bound) and PR #753
  (board deployment guide). Neither changes RTL, firmware or an image input. A trial merge of this head with
  `8eacc408` is conflict-free, and the documentation gates pass on it. The candidate-merge validation is still owed at
  merge time.
- **sv2v version in the processor sweep.** The processor's `tb/nvm_port` Yosys guard fails under sv2v 0.0.12, the
  parent's pinned version, at the old pin `2ad2f845` as well as at `2cbed0a9`, and passes under v0.0.13, which the
  processor's own portability job installs. The counted processor sweep used v0.0.13. Nothing in the adoption changes
  this; it is left for its own issue.
- The parent keeps the processor's `N_AVB_IF_P` and `rx_if_index_i` defaults. Using a second AVB interface is
  separate work.
