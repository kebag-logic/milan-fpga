## 6. Findings and open questions

**Item 1's basis, with the lines that make it true.** lwSRP refuses a receive (`-SHLAN_ERROR_NO_MEMORY`) only where an allocation fails: `get_or_create_attr` and `map_reserve` under `rx_on_attr` (`third_party/lwSRP/src/core/mrp_mad.c:484`, `:543`, `:1020`). Which allocations a replay asks for follows from:
- the receive filter's answers, `interested_msrp` and `interested_mvrp` (`srp_mbx.c:236-283`), which read only the sources (fixed), the sinks' bindings and the Domain's VID. While a receive waits, `srp_mbx_bind` refuses (`srp_mbx.c:469`, `m->pending_rx.len`), and `transmit` makes no declaration and no Domain change (`srp_mbx.c:1076`), so they hold;
- each attribute's existence: created only by an allocation (`get_or_create_attr`, `mrp_mad.c:484`), which leaves the pool no larger, and freed only by `mrp_reclaim` or a participant's destroy, each a block returned (`ctrl_pool.c`, `ctrl_pool_returned`);
- each attribute's states: every Applicant and Registrar change goes through `deliver_event_changed` or the leave timer, each reporting it to the observer (`mrp_mad.c:697-721`, `:878`), `moved()` (`srp_mbx.c:296`);
- each attribute's value: changed only by a receive (only the retained one is taken meanwhile, `rx_ready`, `srp_mbx.c:544`) or a declaration (none meanwhile, above);
- the pool's state: its classes' free blocks, which only a return increases.

So a refusal is a function of the frame, the pool and the attributes' states, and equal counts and a clear flag bracket no change that could turn it: no line found reads anything else, so the second exit does not fire. A retry is now made at most once a centisecond; a give-up past 1 s with a change pending waits at most that centisecond for the retry the change allows, which the README states.
