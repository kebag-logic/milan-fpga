**R531-1-F1 — MAJOR — Conformance, RTL, Robustness, Tests — `sw/firmware/ctrl/acmp/acmp.c:920`, `:968` — Unsupported AVTP versions can change persistent and discovery state.**

Authority/evidence: IEEE 1722-2016 4.4.3.4 requires receive verification and rejection of unsupported versions; IEEE 1722.1-2021 8.2.1.3 and 6.2.2.3 specify version zero for ACMP and ADP. Both new receive validators ignore bits 6:4 of byte 15. The independent tests change only those bits to version 1. A BIND traverses the existing mailbox filter and loop, binds the sink, emits frames and invokes persistence. An AVAILABLE applied to a restored binding advances it from PRB_W_AVAIL to PRB_W_DELAY. The corresponding version-zero controls pass. See [probe source](scripts/independent_probes.cpp), `CoreProbe.UnsupportedVersionCannotBind`, `CoreProbe.UnsupportedVersionCannotDiscover`, and `MailboxProbe.UnsupportedVersionPassesFilterButMustNotBind` in [one-interface](receipts/independent-if1.log) and [two-interface](receipts/independent-if2.log) receipts. The ADP case exercises the delivered firmware entry; it does not assume the deferred ingress term exists.

Impact: frames whose format the implementation does not support are interpreted as connection-management commands or discovery updates, including persistent binding changes. Required outcome: reject unsupported versions before decoding or causing protocol side effects, in both receive paths. Verification: retain valid-format controls and add malformed-version commands, responses and AVAILABLE/DEPARTING cases, including the real adapter path where reachable. The supplied malformed-frame tests cover length, EtherType and subtype but omit this field.

**R531-1-F2 — MAJOR — Conformance, RTL, Robustness, Tests — `sw/firmware/ctrl/acmp/acmp.c:615`, `:1076` — Deferred probes lose part of their 200 ms response interval.**

Authority/evidence: Milan v1.2 Table 5.26 and 5.5.3.5.16 require a duplicate command followed by a 200 ms TMR_NO_RESP; the initial probe procedures likewise send before starting that timer. `send_probe()` starts it before `transmit()` knows whether the frame can leave. `acmp_poll()` later commits the queued frame without updating its deadline. In `CoreProbe.DuplicateGets200msAfterFiveMsSendStall`, relative to the initial send, the first timeout occurs at 200 ms, the duplicate waits for room until 205 ms, but the second timeout still occurs at 400 ms. A matching successful response at 402 ms, 197 ms after the duplicate actually sends, is ignored in PRB_W_RETRY. The same-sequence check passes. An unstalled duplicate accepts a response at 197 ms. Both interface builds reproduce the failure in the receipts above.

Impact: even a five-millisecond stall, within the stated 10 ms service budget, can reject a response within its allowed interval, set LISTENER_TALKER_TIMEOUT and defer recovery. Required outcome: associate the response deadline with the actual accepted send of the relevant attempt, while preserving command order, the single duplicate and its sequence_id. Verification: stalled initial and duplicate attempts must retain the full interval after commit; exercise expiry boundaries, successful responses and cancellation/rebinding while a probe is owed. Existing A10, A19 and the processor walk do not test this combination.

**R531-1-F3 — MINOR — Conformance, RTL, Robustness, Tests — `sw/firmware/ctrl/acmp/acmp_mbx.c:54` — Slot-range validation wraps at UINT_MAX.**

Authority/evidence: `acmp_mbx.h:162` promises refusal when the slots do not fit the fabric timer bank. `first_slot + MBX_N_IF` wraps for `first_slot == UINT_MAX`, so initialization succeeds and stores slot 255 for interface zero. The mailbox has 16 slots and an eight-bit slot field; its timer command rejects 255 and increments BUS_ERR. `CoreProbe.TimerSlotBoundsIncludeUnsignedMaximum` confirms that the last valid range is accepted and the immediately invalid range rejected, but UINT_MAX is accepted. `MailboxProbe.OverflowSlotCannotReceiveItsFabricExpiry` confirms the downstream effect: BUS_ERR rises and the sink remains PRB_W_RESP when it should have retried. Both one- and two-interface runs reproduce it.

Impact: an invalid public initializer argument silently creates a nonfunctional adapter; the default composition uses a valid constant and is unaffected. Required outcome: reject out-of-bank ranges without unsigned overflow or narrowing. Verification: boundary tests must cover the last legal range, first illegal range, UINT_MAX and values that would truncate when stored. This is a missing input boundary, despite raw 100% branch coverage.

**R531-1-F4 — MINOR — Docs — `docs/design/MAILBOX_SPLIT.md:595` — The owed-frame timing conclusion contradicts the bound.**

Authority/evidence: the adjacent table and `acmp_mbx.h:145` give 8,865 accesses for a response behind seven owed frames. At the paragraph's assumed 1 microsecond per access, this is 8.865 ms, below T_svc = 10 ms. The paragraph incorrectly includes that case among bounds that do not fit. The full acmp and adp ring bounds, 10,835 and 21,670 accesses, do exceed 10 ms at that assumption.

Impact: the published service-budget conclusion misidentifies which backlog needs a tighter bound or faster access. Required outcome/exact correction: change “a full acmp ring, a full adp ring or seven owed frames” to “a full acmp ring or a full adp ring”, and state that the 8,865-access owed-frame bound fits under the same assumption. Retain the unmeasured A4 qualification and exclusion of time waiting for room. Verification: recompute all four table rows against 10 ms and the 20 ms ceiling. This changes a timing conclusion and therefore is not wording-only RESIDUE.

**R531-1-F5 — MINOR — Docs — `sw/firmware/ctrl/acmp/acmp.h:396` — The public poll contract describes draining more than one frame.**

Authority/evidence: the header promises oldest-first retries “until one is refused”; `acmp.c:1082` attempts exactly one queued frame per call, even when further frames could send. That implementation is intentional: A19, E2 and the adapter's one-frame-per-pass latency derivation require it.

Impact: callers reading the public interface receive the wrong bound and draining behavior. Required outcome/exact correction: “Attempt to send at most one owed frame, oldest first; return true while any frame remains owed.” Keep the implemented per-pass bound. Verification: compare the corrected contract with `AcmpCore.A19NothingPassesAnOwedFrame`, `AcmpMailbox.E2AnOwedResponseIsCommittedInPassKPlus1` and `acmp_poll()`. This is an interface-contract correction, not a stylistic residue.
