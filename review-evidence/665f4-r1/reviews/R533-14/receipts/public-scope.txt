**Owner direction, 2026-10-05:** write the software side of the Mark II split now, in parallel with the protocol-processor program. The requirement change (#664) still waits for the PP program to finish.

## Scope

Bare-metal firmware on the on-chip RISC-V for:
- **ADP**;
- **ACMP** (decided earlier the same day);
- **MAAP**;
- **SRP** (MRP, with MSRP and MVRP);
- **AECP**: descriptor serving, commands, and the unsolicited notifications. The owner added AECP the same day;
- **the NV memory handling**: read the saved entity state from the flash at boot, apply it, and write it back on change (the #70 saved-state design).

It sits behind the packet-mailbox and ingress-filter contract recorded on #640: block RAM rings, doorbell and interrupt, 32-bit accesses, no DMA, a bus adapter per host, portable C behind a small HAL, one YAML contract. It must port to a hard core.

The fabric keeps:
- framing and timestamps;
- the gPTP plane;
- the timers that carry hard deadlines, posted to the core as events;
- the ingress filter.

## Rules while #664 is open

- Everything lands behind a build switch whose default is the current all-fabric placement. No shipping-image change.
- The firmware builds and is tested on the host against a mailbox model. The existing processor suites' stimulus is reused through that model wherever possible, so each protocol's checks carry over.
- Each protocol states its firmware service-latency bound per response path and tests it, as NFR-SCOUT-03 will require after #664.
- Portable C (C11), no compiler intrinsics in protocol code, and a fixed-width, byte-order-explicit wire layer.

## Lanes (in order)

- **F0, the contract and harness (first).** The mailbox and ingress-filter YAML contract and its generator (fabric module skeleton, C header, docs), the HAL, the host mailbox model and test harness. The ADP firmware is the first vertical slice through it.
- **F1, NV memory handling.** Flash read at boot, validation per the #70 saved-state format (KLJ2), apply, and the write and commit path, ported from `sw/firmware/milan_baremetal` and the processor writer's rules. It can start alongside F0 against the HAL draft.
- **F2, MAAP.**
- **F3, ACMP.**
- **F4, SRP (MRP, MSRP, MVRP).**
- **F5, AECP** (descriptor serving, commands, notifications).

F2 to F5 start once F0's contract merges, so the protocols share one interface.

Relates to #640, #664, #70, and milestone 13.

[A10] **Owner directive, 2026-10-05 12:14: bare-metal first, and reuse lwSRP.** "The solution need to be baremetal first in mind, re-use the lwSRP available on the kebag logic github."

What this changes for #665 and every lane under it:

1. **Bare-metal first.** The firmware runs with no OS: a single event loop driven by the mailbox doorbell, interrupts and fabric-posted timer events.
   - No heap: every allocation comes from static pools sized from the entity model at build time.
   - No dynamic threads, and no OS service in protocol code.
   - An RTOS port (lwSRP has Zephyr glue, for example) may come later as an adapter. It is not the design target.
2. **SRP is lwSRP**, from https://github.com/kebag-logic/lwSRP (MRP, MSRP with FourPacked listener declarations, MVRP, MMRP; ports-and-adapters C11). F4 integrates lwSRP and does not write SRP again:
   - an end-station adapter on the mailbox contract, in place of its switch-oriented `sim_adapter`;
   - a bare-metal port: `shlan_malloc`/`shlan_calloc`/`shlan_free` on a static pool, `shlan_printf` on a debug sink, and `shlan_timer_tick()` at the centisecond, driven by the fabric's timer event;
   - fixes found during integration go to lwSRP as PRs, not as a private copy.
3. **F0's HAL must carry lwSRP's port layer.** The contract must carry MRP PDUs and the timer event in the form lwSRP's `mrp_pdu` codec and timer port take.
4. **The same pattern applies to the other protocols.** ADP, ACMP, MAAP and AECP are written as portable C11 ports-and-adapters modules like lwSRP, host-testable with cgreen and behave where that fits.

F0 (A542) is restarted with this directive, keeping its partial work.

[A10] **Acceptance addition for every F-lane and the default flip: linked firmware size against the block-RAM budget.**

With DDR3 dropped (decision D4, #640 5991591637), the Mark II firmware and its data live in block RAM. Today the F-lanes report object sizes only. Under the 10 % reserve, the XC7A100T leaves about 50 RAMB36 tiles for the firmware after Mark II's fabric changes, which is about 128 KB at 4.5 KB per tile. A firmware near 256 KB would not fit.

- Each F-lane reports the linked RV32 image of the composed `ctrl_app` at its head: text, rodata, data and bss, plus the static pools sized from the entity model. Report it for the shipping shape and the largest supported shape, with the delta from its base.
- The default flip (#664 decision 3) needs a routed Mark II image that shows LUT, FF and RAMB36 use against NFR-RES-01, with the firmware in block RAM.
- If the linked image is heading past about 128 KB, the manager raises it with the owner before the flip. The fallback is the XC7A200T (AX7201), which needs no RTL change.
