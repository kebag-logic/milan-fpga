--- README lines 869-888
   869	**This suite backs no descriptor memory, on purpose and on record.**
   870	`milan_datapath` exposes nine ports for the AEM image the store fetches
   871	(`o_desc_mem_req_valid` … `i_desc_mem_rsp_err`). Every leg here drives
   872	`i_desc_mem_req_ready` **low explicitly**, in the reset section, next to a
   873	comment that says what that means: it is `KL_aecp_desc_store`'s documented
   874	degrade path — the watchdog abandons the burst, the image never validates, and
   875	`READ_DESCRIPTOR` comes back well formed but empty-handed. A zero left at a port
   876	by accident and a zero driven by a decision look identical on a waveform, so it
   877	is stated. The `[AECP]` checks in `sim_nxn.cpp` grade that path: an answer
   878	arrives, it is an `AEM_RESPONSE`, its status is `BAD_ARGUMENTS` (an unvalidated
   879	image reports `configurations_count = 0`, and the µprogram range-checks the
   880	configuration index *before* it locates, so this is not
   881	`NO_SUCH_DESCRIPTOR`), it carries the Section 7.4.5 stub at `cdl = 20`, and it is
   882	padded to 60.
   883	
   884	**The SERVED path lives in `tb/verilator/pp_shadow`**, which backs those ports
   885	with a real `AEMI` image and grades `SUCCESS` with the descriptor bytes compared
   886	octet for octet, the locate miss, the bad configuration index, the
   887	`NOT_IMPLEMENTED` echo, the two silent-refusal cases, and the no-memory degrade
   888	with recovery.
