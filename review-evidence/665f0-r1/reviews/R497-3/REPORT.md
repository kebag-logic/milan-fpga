**R497-3-F1 - MINOR - Conformance, RTL (firmware architecture), Robustness, Tests, Docs - A full departure counter silently drops the next shutdown.**

- **Artifacts:** `sw/firmware/ctrl/adp/adp.c:170`; `adp.h:33`; `docs/design/MAILBOX_SPLIT.md:289`; standing queue tests in `test_adp.c:328`; `scripts/queue_capacity_probe.c`; `receipts/queue-capacity.log` and `.rc`.
- **Authority/evidence:** round-3 item 1 requires an owed departure never to be lost, with no undocumented enable-API precondition. Milan 5.6.3.5.11 requires DEPARTING for SHUTDOWN in DELAY. The new header and design page promise preservation across subsequent shutdowns. However, `shutdown()` increments only while `departing_owed != UINT32_MAX`; at the maximum it still ends the run and disables the entity, without transmitting, recording, rejecting or reporting the additional departure.
- **Reproduction:** the unchanged implementation receives 4,294,967,296 pairs of public `adp_set_enable(true)` / `adp_set_enable(false)` calls. Link is up, each shutdown occurs in DELAY, and the send port refuses every frame. No private field is planted and no implementation is mutated. The completed run records 4,294,967,295 owed departures, zero accepted frames and one unrecorded departure; exit 1, elapsed 39.12 seconds on the review host. A 10,000,000-pair control records every departure and exits 0. These are host execution times, not target timing measurements.
- **Impact:** at this extreme sustained backlog, at least one required shutdown message becomes unrecoverable. Saturation avoids wrapping the whole queue to zero but does not preserve the additional obligation. The header's statement that the counter reaches `2^32 - 1` discloses its width; it does not define an accepted loss policy or a caller-visible refusal. The design page and PR still make an unconditional preservation claim. Standing tests exercise small queues and do not detect this capacity behavior.
- **Required outcome:** define and implement non-silent capacity handling consistent with the accepted contract. If a finite service/backlog precondition or deliberate coalescing is intended, obtain a public scope decision and reflect it in the API and authoritative documentation; do not silently infer an exception to the frozen no-loss criterion. Merely widening the counter moves the same boundary.
- **Verification:** add a capacity-boundary test observing the declared outcome, including the last representable obligation and the next shutdown. A reduced-capacity fixture or controlled boundary state can keep it fast. Retain A15/E4, A16/A17, ordering, index and access-bound checks, with a named mutation for the chosen capacity rule.
