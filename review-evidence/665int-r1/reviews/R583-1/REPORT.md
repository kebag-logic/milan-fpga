### R583-1-F2 - MINOR - Tests - `sw/firmware/ctrl/test/test_maap_mbx.cpp:125-145` (helper `:86-91`) - the DA gate's interface routing is untested; a gate written to the wrong interface passes every MAAP test

- **Evidence.** Reviewer plant `rv-maap-gate-on-interface-0` changes `sw/firmware/ctrl/maap/maap_mbx.c:62` from `mbx_pub_da_gate(interface, ...)` to `mbx_pub_da_gate(0u, ...)`. That includes `DaGateIsPublishedBeforeEachAllocationIsReported` and its check "DA gate of another interface is its own" (`:139`). That check cannot fail for this defect: `acquire()` releases every other interface before acquiring interface 0 (`:88`), so only interface 0 ever reports an allocation. None of the author's MAAP plants (`pub-maap-*`) varies the interface.
- **Impact.** In a two-interface split build, interface 1's talker DA gate would never open, and its allocation reports would overwrite interface 0's gate. The block's per-interface isolation is proved in RTL (P1, P2) and in the driver (D14), but not at the adapter that chooses the interface. AGENTS.md section 6, Tests lens: "Each new test can fail for the defect it claims to detect".
- **Required outcome.** A named test at two interfaces in which interface 1 (or both) acquires and each interface's `DA_GATE` is asserted on its own, before its own report. `rv-maap-gate-on-interface-0`, or an equivalent wrong-interface plant, joins `ctrl_mutants.py` and is killed by that test on its words.
- **Verification.** `test_ctrl_firmware.py --self-test` lists the new plant as caught by the named test at two interfaces.
