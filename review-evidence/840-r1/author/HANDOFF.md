## Finding made on resume (17:4x), fixed in d62417f1

The retired Arty recipe (`phy: mii-100`, DP83848 10/100 PHY, LiteEthPHYMII 10/100 MAC) routes
MDIO (`litex_boards` digilent_arty `eth` has mdc/mdio; LiteEthPHYMII builds LiteEthPHYMDIO), so
`CSR_MILAN_MAC_PHY_MDIO_W_ADDR` exists there and the unconditional init of 725c751a would have
stripped the DP83848's only abilities: an Arty image would never link. The issue's premise
("The MAC is 1 Gb/s only") holds for the AX7101 GMII build only (`sw/litex/milan_soc.py`
`_BOARD_PHY_MODEL`, `_PHY_MODEL_MIN_MBPS`). d62417f1 writes the advertisement only when the
PHY reports 1000BASE-T full duplex ability (IEEE 802.3-2022 22.2.4.2.16 bit 1.8, 22.2.4.4.3
bit 15.13); bit 1.8 comes from the poll's own register 1 read so a latched loss
(22.2.4.2.13) stays the poll's to publish. AX7101 behaviour is exactly the issue's.
Material assumption, published in REVIEW READY and the PR.
