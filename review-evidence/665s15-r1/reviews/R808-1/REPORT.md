## 3. Findings

### F1 - MAJOR - Conformance, RTL, Robustness, Tests, Docs

`third_party/tsn-c-stack/src/acmp.c:816`, `:871`, `:310`, `:1225` (pin 70936b77), made reachable by `sw/firmware/ctrl/test/ctrl_srp_image.py:77-89`. Misstated at `docs/design/SHAPE_32X32_CENSUS.md:242` and in the PR body's Findings.

**Title:** the 32-bit ACMP owed-release mask is used at 33 sinks in the image this PR builds.

Requirement and evidence:
- `acmp_sizing` builds the 32x32 image with `-DACMP_MAX_SINKS=33u` (`receipts/images/head/endstation_ax7101_32x32-if2/size.json`).
- In that image, `bind_response` and the unbind response compute `1u << k`, and `transmit`'s and the release loop's `(release >> k) & 1u` run for k up to 32, against `uint32_t release` (`include/acmp.h:400`).
- Shifting a 32-bit value by 32 is undefined in C11 (6.5.7p3).
- In the linked 32x32 image (`ctrl_app.elf` sha256 5b0c3ce2..., identical to the published one), the pinned RV32I compiler emits `sll a3,a3,s3` in `bind_response` and `srl a5,s2,a4` in the change-owed loop (`receipts/gates/acmp_bind_response.dis`, `receipts/gates/acmp_transmit_loop.dis`). RV32I uses only the low five shift bits, so sink 32 (the CRF sink) and sink 0 share one release bit.
- Consequence: an owed response for either sink increments and releases both sinks' `change_owed`. Each sink's change notice is held behind the other's owed response.
- The census and the PR body say the opposite: "that sink's change notice is not held behind its owed response".
- The defect has no owner issue. The census cites #653, which is CLOSED; the PR lists the item under "Findings, each needing its own issue", and none is filed.
- The round 2 ruling's item 4 premise ("ACMP_MAX_SINKS ... which acmp.h already allows. No donor patch is needed") does not hold. AGENTS.md section 2 asks for such a conflict to be published as needing a decision before proceeding; the lane proceeded and measured on the image.
- No test reaches the defect. Every harness ACMP probe binds sink 0 or 1 (`tb/verilator/ctrl_service_budget/scenario.py:317-339`, `:598`, `:760`, `:972`), and the host SRP shape suite is not built for this shape (`sw/firmware/ctrl/test/srp_arms.py:148-162`).

Impact:
- Undefined behaviour is linked into the firmware that S2's harness measures at 32x32.
- At this shape, Milan's response-before-notice ordering (the rule #653 enforced) is wrong for sink 0 and the CRF sink: each holds the other's notices.
- The authoritative census describes the failure wrongly, so a reader of it would look for the wrong symptom.

Required outcome: the 33-sink build no longer executes a shift by 32 in the owed-release path. That means either a stack whose mask follows `ACMP_MAX_SINKS` at the pinned gitlink, or a maintainer decision, recorded on #859, accepting the alias at the simulation shape with an open owner issue. In both cases, the census and the PR body state what the RV32 image actually does.

Verification:
- Disassembly of the rebuilt 32x32 `bind_response` and `transmit`.
- A test that binds sink 32 and sink 0 at 33 sinks (a host build with `-fsanitize=shift`, or a harness probe on index 32) and requires each notice held only behind its own owed response.
