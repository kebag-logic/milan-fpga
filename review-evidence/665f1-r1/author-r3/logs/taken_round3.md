Interpreted scope, one line per item:
1. Decision 2. Boot judges each slot at most 3 times, one read each. An OK verdict stands on one read, because its CRC-32 covers every byte, the sequence included. Any other verdict, BLANK included, stands only when two reads agree. A read the port fails, or reads that never agree, leave the slot UNREAD: VD_LEN, plus a bit in a new status field `unread`. The chosen slot's re-stage is tried at most 3 times; a slot that never re-stages as judged is UNREAD, and the other slot is offered. Any UNREAD slot puts the writer in a new HELD phase until reset: changes are marked and reported dirty, nothing is erased or written, and the console is refused. The restore still offers the accepted slot (section 7). No sequence is ever read from a slot that did not pass. The check covers both orientations at SEQ 1, 5, 0x80000000 and 0xFFFFFFFF. Each case runs a transient refusal, a change, a clean reboot, a change, a verified commit and a clean reboot, and the restored payload is compared each time. The planted control `unread_not_held` restores the generation restart and must fail.
2. Decision 1. FASTCONNECT section 7 reads `>= 0` (A on a tie), citing 5997929153. `newer_wins` gains a tie at the wrap, and `tie_picks_b` stays as the failing control.
3. Service bound. The LiteSPI port gets a per-call deadline on `timer0`, in addition to the per-wait poll cap, so a controller that keeps progressing slowly cannot hold one call past a stated figure. Runs with no stall are held to a derived nominal per-call figure, and every run to the cumulative bound. A new case delays every wait. The README and PR separate the measured nominal figures, the cumulative bound and the derived CPU figures, and the "210 us" is corrected to the suite's real maximum, scoped.

Stated readings (each also goes in the README and HANDOFF):
- Two reads that disagree about one slot are a media fault, not a content refusal. A blank verdict needs the same confirmation, because a misread blank slot is as dangerous as a misread refusal: the generation would restart below a container that survives.
- The read retry is bounded at boot. A slot still UNREAD after the bound keeps persistence held until the next reset, whose boot reads the slot again. Limit: a fault that corrupts a slot the same way on every read cannot be told from content.
