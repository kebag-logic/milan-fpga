P-N-AVB-INTERFACES, the redundancy seam, is threaded through the fabric build rather than closed by decision. The top exposes it as
`N_AVB_IF_P` (1 or 2, default 1). At 1 no cell changes anywhere, and the OOC 1x1 delta is **0 LUT, 0 FF**. At 2 the seam is keyed
in ADP, on every transaction, in the registry and in the AVB_INTERFACE counter rows. Three suites build it at 2, and the real top is
linted at 2 on every run of `tb/pp_top`.

## 1. The seam (items 1 to 3)

**Top.** `parameter int unsigned N_AVB_IF_P = 1` (F01.5 P-N-AVB-INTERFACES). Any value other than 1 or 2 is refused at elaboration
with a message naming it: Milan's redundant pair is what is elaborated and graded, and 4 does not fit the 8x8 timer map's 8-bit owner
tags. The count reaches:
- `KL_adp_engine` `.N_IF_P (N_AVB_IF_P)`, replacing the literal `1` (ticket's `:1569`, now `:1973`), and the F08.4 timer map;
- `rx_if_index_i[1:0]`, a new top input with default `2'd0`, read with the frame's last byte and only above 1. It is carried to the
  header beat three clocks later and drives the normalizer's `rx_if_index_i`, replacing the hardwired `2'd0` (ticket's `:1329`, now
  `:1720`). A one-interface parent leaves it unconnected: the parent's wiring is unchanged (section 6).

**Registry (item 2).** With `N_IF_P` above 1, `KL_aecp_notify` stores the port per row, the AVB interface a REGISTER arrived on, and
REGISTER and DEREGISTER walk for the whole Milan v1.2 5.3.4.2 tuple {Entity ID, MAC, port}. A controller registered on both
interfaces holds two entries with Sequence IDs of their own. At 1 the field is not generated. The port is `rgy_port_i`, driven by
the top from the ingress interface of the command the engine is running, latched on the handshake that loads the engine's `cmd_r`.
The engine is untouched.

**Counters (item 3).**
- Keyed per interface: the Table 5.22 GET_COUNTERS rows in `KL_aecp_notify`. AVB_INTERFACE 1 gets the slot after CLOCK_DOMAIN 0,
  so it has a one-second window of its own. Index 0's slot and CLOCK_DOMAIN 0's do not move, and `counter_event_map`, whose every
  line C7's patches hold, is untouched. GET_COUNTERS reads are keyed by descriptor_index through the integrator's `ctr_*` face, as
  they were.
- Not keyed, and why: the processor's own counters (snapshot words 4 to 9, 24 to 29 and 32 to 37) count the shared trunk and engines,
  and keying them would change the register map; the Milan Table 5.1 AVB_INTERFACE counters are the integrator's (GAP-05); the
  GET_AVB_INFO and GET_AS_PATH pushes name AVB_INTERFACE 0, because their strobes are one per top.

**What is not keyed, by design** (the banner, 01 section 7 and the REQ-SCP-003 Arch cell name each one): the MAC trunks (no frame
carries an egress interface out); the class-D levels `link_up_i`, `gm_change_i`, `gm_id_i` and `gptp_domain_i`, which every
advertise machine reads; the SRP engine; the registry depth (P-N-CONTROLLERS in all, the 16 owner tags); the availability monitor
({Entity ID, MAC} on any interface); the side-port snapshot and `adp_next_avail_index_o`, which show interface 0. A per-interface
class-D face or an egress index would be a port change outside this lane.

## 3. Two interfaces (item 5)

Each new check fails under at least one planted control (section 6).

- **`tb/adp_engine`, second build `interfaces`** (`sim_if2.cpp`, section IF): `KL_adp_engine` at `N_IF_P=2`.
  - IF0: both advertise machines reset to DOWN with available_index 0.
  - IF1, IF3, IF7: each interface's link brings its own machine up, or takes it down, alone.
  - IF2, IF8: each ENTITY_AVAILABLE is byte-exact, with its own interface_index, grandmaster and domain.
  - IF4: each interface's frames carry its own available_index.
  - IF5: ENTITY_DISCOVER restarts only the machine of the interface it arrived on.
  - IF6: GM_CHANGE re-advertises only its interface.
  - IF9: disabling the entity sends one byte-exact ENTITY_DEPARTING per interface.
- **`tb/aecp_notify`, third build `interfaces`** (`port_tuple.hpp`): `KL_aecp_notify` at `N_IF_P=2`.
  - PT2 to PT7: the registry tuple. The same Entity ID and MAC on two ports holds two entries, each refreshed, notified with its
    own Sequence ID and deregistered by its own port.
  - CK1 to CK5: AVB_INTERFACE 1's GET_COUNTERS row has its own descriptor index and its own one-second window. Index 0 goes out in
    the same second, index 2 names nothing, and CLOCK_DOMAIN 0 keeps its slot.
- **`tb/pp_top`, seventh build `interfaces`**: the real top at `N_AVB_IF_P=2` (`pp_top_wrap.sv`), with `rx_if_index_i` driven by
  the bench.
  - IF1: each interface's advertise machine sends its own ENTITY_AVAILABLE.
  - IF2: ENTITY_DISCOVER on interface i restarts interface i's machine, for each i.
  - IF3 and IF3b: REGISTER from one controller on both interfaces makes two entries, and DEREGISTER on interface 1 removes
    interface 1's.
- **`tb/pp_top` `if-guards`** (`if_guards.py`, run by every `make` of the suite): the real top is linted at 1 and 2, clean, and at
  0 and 3. At 0 and 3 it must refuse with the message naming `N_AVB_IF_P`.

The planted controls that collapse the interface index (the item 5 mutant) fail them:
- `if-ingress-collapsed` and `if-ingress-forced-one`, in ADP;
- `if-top-ingress-collapsed`, the top's index tied to 0, which fails pp_top IF2, IF3 and IF3b;
- `rgy_port_tied_zero`, the registry port tied to 0, which fails IF3 and IF3b.
