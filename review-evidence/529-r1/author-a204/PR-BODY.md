## Description

The declared CRF Media Clock Input (STREAM_INPUT index `N_STREAMS`) answered GET_COUNTERS with
an empty mask. `KL_crf_rx` kept all ten Milan Table 5.16 counters, but seven of them and its
dirty pulse were left open at the root. A Milan controller therefore rated the entity IEEE
1722.1 only. This closes the REGISTER_MAP closure criteria 1-4 at the root. It makes no
processor change and no pin change.

| Piece | Change |
|---|---|
| `hdl/milan/milan_datapath.sv` | The seven open `KL_crf_rx` tallies and `dirty_p_o` are connected. A new gather-face row (`ctr_crf_w`, `ctr_crf_block`) serves STREAM_INPUT `CRF_SNK_IDX_C` only when the shape declares the CRF sink. It serves the ten at their Table 7-157 quadlets, full 32-bit, under `counters_valid = 0xF3F`. The Table 5.22 arbiter's STREAM_INPUT pending vector widens by the declared CRF sink (`PP_CTR_SIN_N_C`), so the pulse is delivered as {STREAM_INPUT, `N_STREAMS`}. The processor already keeps that row (`N_STREAM_IN_P = ACMP_SINKS_C`). |
| `hdl/ieee1722/crf/KL_crf_rx.sv` | Comments only: who serves the mask, and what the lock tallies are. |
| `tb/verilator/milan_dp/sim_nxn.cpp` | `[CTRS-CRF]` (54 checks on each broad leg) and the timed leg's `[NOTIFY-CRF]` (8 checks). |
| `scripts/port_docs.budget` | Regenerated by the tool. |
| docs | REGISTER_MAP (the gap closed, with a quadlet table and evidence per criterion), compliance matrix 5.4.2.25 -> `implemented`, audit B4, REGISTER_MAP_CLASSES, roadmap, FR_NFR, builder page, milan_dp README, CHANGELOG (unreleased). |

The mask is a published interpretation: Milan keeps the IEEE Stream Input offsets, and only
Table 5.17 compacts, and only for Stream Outputs. This matches the repository's counters
contract ("Milan Table 5.6 is exactly ten counters, in the 1722.1 block order", mandatory wire
mask `0xF3F`). TIMESTAMP_VALID and TIMESTAMP_NOT_VALID stay unclaimed because `KL_crf_rx`
keeps no tally for them. The AAF inputs keep `0xFFF`.

Area: focused generic synthesis of `milan_datapath` goes from 1,631,301 to 1,632,435 cells
(+1,134, +0.07%). The growth is the seven 32-bit tallies and their incrementers, which
synthesis used to remove as unread, plus the answer arm and one arbiter row. No other top
contains `milan_datapath`.
