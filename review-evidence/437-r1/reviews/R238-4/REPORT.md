## Findings

### F1 - MAJOR - Conformance, Robustness, Tests, Docs - `scripts/gen_toc_renderer.py:257` - the position-attribute guard is case-sensitive, so raw HTML can list a heading GitHub hides and win the em-dash exemption for it

- **Authority.** #516's objective: "The Contents walk must not authorize labels for headings absent from the rendered page." CONTRIBUTING.md 6.1 (lines 593-599) states the three remaining limits "each one withholds a heading; none can grant an exemption". docs/DOC_GENERATION.md:62-63 says the same, and so does `scripts/gen_toc_renderer.py:40-44,255-256` ("withholds a heading and cannot invent one").
- **Defect.** `render()` gives up on a page only when the page contains the literal lowercase `data-sourcepos`. HTML attribute names are ASCII case-insensitive, and html5lib lowercases them. A raw `<h2 DATA-SOURCEPOS="L:1-L:C">x</h2>` therefore survives the guard and is parsed as an `h2` carrying position `L:1-L:C`. When that position is a heading hidden by GitHub (here, one inside a raw `<!--` the page leaves open, the #516 family), `_page()` finds it in `shown`. It lists the hidden heading with the label read off its own source line, and labels that line prose instead of commented.
- **Evidence, local.** I used this page: `<h2 DATA-SOURCEPOS="6:1-6:18">x</h2>`, then `<span>`, `<!--`, the hidden `## Old <em dash> heading`, `<!-- -->`, and `## Alpha`. `headings()` gives `[Old <em dash> heading -> old--heading, Alpha]`. The control without the raw tag gives `[Alpha]`. A mixed-case spelling gives the same result as uppercase.
- **Evidence, GitHub.** GitHub renders the same pages in gfm and file-view mode. Neither shows `Old <em dash> heading`. The file-view ids are `x, alpha` (and `page, contents, alpha, x, beta, gamma` for the end-to-end head page), never `old--heading`.
- **Evidence, end-to-end.** I ran the shipped `check_em_dash.py --base` on real Git commits. The control commit pair is refused (rc 1). In the pair that differs only by the raw tag, the gate reports 0 findings and "1 mirrored label(s) exempt" (rc 0). That exemption covers a label whose heading GitHub renders at neither the base nor the head, while the Contents link `#old--heading` points at an anchor the page does not have. This is the escape direction #437 and #516 exist to close.
- **Why the fixture passes.** `gen_toc_shape_cases.py` compares `rendered_headings()`, the text of whichever element carried the position ("x"), with GitHub's text. It never compares what `headings()` lists (label and anchor) with what GitHub renders. So my probe script marks these spoof pages "agree" in both modes (`probes/set2.txt`, `probes/set4.txt`), and a shape of this kind added to the fixture would pass as well.
- **Impact.** An author who writes raw HTML can obtain the em-dash exemption for a label mirroring a heading the page never renders, and ship a Contents link to a missing anchor. The "cannot invent one" guarantee in the authoritative CONTRIBUTING.md 6.1 is false as written.
- **Required outcome.** No spelling of the renderer's position attribute that the HTML parse reads as that attribute can reach `_page()`. The guard must hold in every ASCII letter case, or equivalent: any design that makes raw HTML unable to supply a position. The three documents must then state what is actually true. An arm must fail when that property is removed: a case-variant page in the renderer arms and in the real-Git em-dash rows. At least one arm must compare `headings()` labels and anchors (not only rendered text) against a recorded GitHub rendering. My probe `M22` shows that `POSITION in text.lower()` keeps all 1433 TOC arms and all 332 em-dash arms green (`receipts/mutations.txt`), so a fix has room.
- **Verification.** Re-run `scripts/emdash_spoof_e2e.sh`: the spoof variant must be refused like the control. `probes/set2-pages.json` must list no hidden heading. Check that the new arm fails with the guard reverted.
- **Receipts:** `probes/set2-*`, `probes/set4-*`, `receipts/emdash-spoof-e2e.txt`, `scripts/emdash_spoof_e2e.sh`.
