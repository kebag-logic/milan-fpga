## Real limits

- L1: a comparison's inputs are taken by construction from the shipping route, because its script opens the shipping checkpoint path. The gate cannot tell a stale comparison directory, one placed from an earlier checkpoint at the same path, from a fresh one. If such a stale route were selected, its resources would be judged instead of the change's. The same holds for stale reports in a shipping directory. The recipe's fresh-directory rule (`output.mkdir()` in the snippet, and "Run each measurement in a fresh directory") is the control. This is not a finding against this PR.
- L2: `--shipping-selection` is trust-based. An adopter can mark the shipping route alone even when another directive has the better WNS. The issue provides the mark, and the ruling's "the shipping image is built from that best directive" stays a manual seed selection, as the PR states.
- `gen_toc.py --verify-anchors` and `--check` did not run here: the pinned Markdown renderer is not installed and installing it is out of bounds. The author's docs receipts report them green.
