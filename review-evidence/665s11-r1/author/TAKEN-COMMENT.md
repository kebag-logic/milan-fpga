Interpreted scope: the firmware's AECP owner answers REBOOT (0x002A) as 7.4.43 and the processor do. It answers BAD_ARGUMENTS for a command shorter than Figure 7-68's four bytes, NOT_SUPPORTED for a type other than ENTITY, NO_SUCH_DESCRIPTOR for another ENTITY index and ENTITY_LOCKED under another controller's lock. Otherwise it answers SUCCESS, notifies the other registered controllers and takes no further command. Once those frames have left the mailbox, ADP's SHUTDOWN sends ENTITY_DEPARTING. Once that has left too, the platform reset port fires #822's reset (drain, egress wait, PHY hold, IPROG), unchanged. dev-soft-core ties the split's request to 0 (milan_datapath.sv:10143). So this lane adds the smallest CPU-driven port with no mailbox contract change: a one-bit CSR in the split SoC, crossed into the datapath clock by a MultiReg, onto KL_reboot_ctrl.reboot_req_i. The saved-state code is tested as it is; #823 owns any format change.
