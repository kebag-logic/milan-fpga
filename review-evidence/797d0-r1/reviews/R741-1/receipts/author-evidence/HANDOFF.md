## Generator and freshness gate

- Population: every tracked `*.md` and README (`git ls-files`; a `.gitmodules`-aware walk without Git); the audit
  page's own row is rendered from its header, so the page cannot depend on itself.
- Columns: area, lines, audience (`Audience:` line or the `AUDIENCES` table), purpose (first `#` heading),
  describes (top three cited tracked directories, a submodule path standing for its submodule, plus cited
  standards), status with evidence, verified (D0 / area lane / archive), lane.
- Status rules: archive -> obsolete (successor from the banner); a supersession banner or a recorded judgement ->
  superseded; a recorded finding -> stale; else current (generator named when generated).
- Result at the head: 210 documents, 89,111 lines; current 182, stale 7, superseded 0, obsolete 21.
- Gate: `python3 scripts/docs_inventory.py --check` (rc 1 when stale, 2 on a refusal); `--selftest` 21 controls.
- Planted stale-page mutants in the real tree (`receipts/mutants/planted-mutants.log`): one line appended to
  `docs/guides/PROJECT_MANAGER.md` -> rc 1 (`STALE (3 lines differ)`); a new tracked page -> rc 1; the D0-001
  statement corrected -> rc 1 and the row renders `re-verify: quote not found`; a hand edit of the page -> rc 1;
  each restore -> rc 0; final tree clean.
- Meta-mutants (`receipts/verification/meta_mutants.log`): 8 in-memory breakages of the generator (line count,
  locate, em-dash rewrite, status, archive successor, audience override, describes, data refusals) each make
  `--selftest` fail; 0 survivors.
- Determinism: `--check` passes in a `git archive` export (no `.git`, no submodules) and in a

Design consequence for review: the page carries every document's line count, so any PR that edits a Markdown file
must rerun `python3 scripts/docs_inventory.py --write` (as `gen_toc.py --write` is rerun for headings), and the
next `dev-soft-core` sync must regenerate it. That is what "generated, never hand-edited, freshness-gated" costs.
