## 1. Allowlist (direction item 1)

Where it runs: the first statements of `assert_within_lexical_subset()`, before the literal, digraph, `$`, UCN, `__has_include`, header-name and `_Pragma` checks, and so before any reader. The check is inline, not a helper, so the reviewers' unchanged AST extractors still load it.

Its pin is `SUBSET_CHARACTER_PIN = "spells a character outside the allowlist of S"`. Its constants are module-level, `_C_S_CHARACTERS`, `_C_S_OUTSIDE_RE` and `_C_S_UNDECODED_RE`. They use the `_C_` prefix the reviewers' extractors load.

**Outside a comment and a string or character literal**, the exact admitted set is:

- printable ASCII, U+0020 to U+007E;
- the six characters the readers model as whitespace or a line end: HT 0x09, LF 0x0A, VT 0x0B, FF 0x0C, CR 0x0D, NUL 0x00.

Every other character is refused by name with its code point and line. That includes every non-ASCII character, every other control (0x01-0x08, 0x0E-0x1F, 0x7F) and a UTF-8 byte-order mark at offset 0. The check is `_C_S_OUTSIDE_RE.search(_c_phases(source).code)`, plus an explicit test for the mark at offset 0, because phase 1 blanks that mark in the code text. `$` and `\` are printable ASCII: the allowlist admits them and the later S rules refuse them by their own pins, as before.

**Inside a comment or a literal**, any UTF-8 character is allowed. A reader never sees it:

- `_c_phases()` blanks every comment and every literal body in the phase-3 view, which every directive and macro reader reads, and in `blanked()`, which every other C text rule reads.
- The two checks that read raw text, the trigraph ban and the `#include` operand check, match ASCII spellings only.
- The lexer finds comments and literals from ASCII characters alone. Its raw-prefix test now uses an explicit ASCII set, `_C_IDENTIFIER_CHARACTERS`, instead of `str.isalnum()`. So its raw-literal detection covers everything GCC treats as a raw literal, and no character outside the set can move the boundary the allowlist relies on.

**A byte that is not UTF-8** is refused wherever it sits, a comment included; GCC reads the file as UTF-8 too. The firmware read is now `read_text(encoding="utf-8", errors="surrogateescape")`, so such a byte reaches S as an escape and S names it instead of the read failing. I kept `read_text` rather than `read_bytes` on purpose: R272-2's split-digraph probe patches `Path.read_text`.

**The byte-order mark at offset 0 is now refused.** The direction says "every non-ASCII byte". Round two had accepted this mark (phase 1 drops it, as GCC does). This round:

- turns that accepted case into a mutation entry, so accepted edits go from 30/30 to 29/29;
- re-pins the three entries for directives behind the mark (the paste forgery, the second `#include` and the `#line`) onto the allowlist pin. The paste ban, the include pin and the directive set keep their other entries.

The fixed lexer corpus keeps its BOM spellings, because they still measure the shared lexer.

**The shipping firmware is inside S**: 59,394 bytes, all printable ASCII plus 1,640 LF and 1,344 HT.

## 3. Closure table and generator (direction item 3)

  - The 9 positions: at offset 0 before `#`; in a line's lead before `#`; between `#` and a directive name; inside a directive name; after one; inside an identifier in code; inside a block comment, a string literal and a character literal.
- Record: `_CLOSURE_KEPT` holds GCC's answer for every cell. It was recorded on the pinned `riscv32-linux-gcc` 14.3.0 with `<out>/tools/record_closure.py`, which measures exactly as the gate does.

  - it is refused by S, or the readers keep what GCC recorded;

  - wherever the RV32 compiler answers, every cell is re-measured.

- `lexer_keeps` now skips a group nested in an arm already dropped (GCC skips it whole). Before, a nested `#if` in skipped code returned "no corpus entry spells" instead of nesting. The lexer corpora are unchanged by this: 1845/1845.
