Campaign drivers use --jobs 1; four independent campaigns run concurrently. Each build initially has two CPUs; the two D3 workers were expanded to four CPUs once the external probes finished and memory use fell below 6 GiB. MAKEFLAGS=-j16 throughout. No verdict or source changed.
The name, stream-info, notification and ACMP campaigns also run through two early queues, with a per-campaign exclusive lock so the main queue reuses their completed records. No validation command is duplicated by these queues. The final command controls also run ahead once the baseline controls release their slot. These locks are distinct from the unused hardware-tool lock.
After memory reached the cap without an OOM kill, the campaign PATH binding was changed from a symlink to a wrapper that appends --build-jobs 2 to the same pinned simulator. This limits subsequent compilation workers; source, simulator and verdicts are unchanged. Existing builds finish normally.
The queued AECP and counter campaigns use --jobs 2 with the compilation limiter; all other drivers use --jobs 1. Their CPU masks include the CPUs released by the full suites. The source and recorded checks are unchanged.
Both full-suite process trees were allowed all 16 available CPUs for their final multi-configuration builds; the original two-CPU affinity had left many compiler workers competing on two cores. No command, source or check changed, and no process was restarted.

The remaining independent notification, ACMP and head-counter drivers also run concurrently through the frozen runner, sharing the same four compilation slots and per-campaign duplicate-prevention locks.
