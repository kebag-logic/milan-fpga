## Findings

### F1 - MAJOR - the gate does not hold 10 of 31 response sizes or any command size, while REQ-VER-002, 09 §8.10, the gate docstring and the PR body say every response size is gated

- Lenses: Conformance, Tests, Docs.
- Where:
  - `scripts/check_aecp_commands.py:681-696` (`fits`). A length the walk widened to `variable` passes any rule with `per` or `plus` (:688-689). A header-only length (cdl 12) passes any echo rule whatever its cdl (:686-687).
  - `scripts/check_aecp_commands.py:403-414, 422-423`: the walk widens to `variable` at the first unknown loop or copy and stops tracking the fixed part.
  - Claims: `scripts/check_aecp_commands.py:35-36` ("every response it sends is the table's size"); `docs/architecture/09_verification.md:482` ("every response and unsolicited body has the table's size"); `docs/00_MILAN_COMPLIANCE_REVIEW.md:535` REQ-VER-002 Arch ("response size on every path of the generated ROM"); the PR body ("Every response and unsolicited body has the table's size"; "Drift the gate found ... GET_AUDIO_MAP 32 + 8·N").
- Evidence. Each probe was applied to a fresh copy of the head export, with F06.14 regenerated by `--write` where the table changed:
  - `receipts/size_sweep.log`: each served command's response cdl +4. The gate fails for 21 commands and passes for 10: ACQUIRE_ENTITY, READ_DESCRIPTOR, REGISTER_ and DEREGISTER_UNSOLICITED_NOTIFICATION, GET_AVB_INFO, GET_AS_PATH, GET_AUDIO_MAP, ADD_ and REMOVE_AUDIO_MAPPINGS, and GET_DYNAMIC_INFO. Each command cdl +4 passes for all 31.
  - `receipts/gamap_base_size.log`: GET_AUDIO_MAP response cdl 20, 24 and 28 all pass, and F06.14 is regenerated each time. That includes "32 + 8·N B (cdl 20 + 8·N ...)", the base tree's wrong value, which the PR credits the gate with finding.
  - `receipts/rom_size_probe.log`: a ROM-only drift NOPs the first BUILD_FIELD or APPEND that E_RDESC, E_GAVB, E_GASP or E_GAMAP can reach. This is the same mutation the self-test uses for E_GSTRI. The gate passes all six; the same mutation on E_GSTRI and E_GCTRS fails by name.
- Authority: lane scope "A drift in any consumer (ROM data, engine constant or doc row) fails by name"; acceptance 1 (sizes in the table) and 4 (REQ-VER-002 Arch records what is gated); issue #73's own motivating defect (F06.14 sizes drifting from the engine).
- Impact:
  - For these rows the issue's defect class is still open. A wrong size can enter F06.14 through the table, or the ROM can change a variable response's fixed part, and `make check` stays green.
  - The compliance matrix and 09 §8.10 claim a coverage the gate does not have.
  - The parent's follow-up firmware lane is told to consume these sizes as the single source.
  - 09 §8.10 does disclose the command-length floors as hand-written. It does not say that the table's command-size column and these 10 response sizes are held to nothing.
- Required outcome, either of:
  - (a) Hold these sizes. For example: keep the fixed length at the point the walk widens and compare it with the rule's base cdl. Hold echo rows' response cdl to the command cdl. Hold command cdl to the engine's decode floors, or record that it is held to nothing. Then add planted drifts for GET_AUDIO_MAP response cdl 20 and 28 (doc regenerated) and a NOPed header field in E_GAMAP, E_GAVB, E_GASP and E_RDESC, each failing by name.
  - (b) Narrow every claim (gate docstring, 09 §8.10 table and "still hand-written" paragraph, REQ-VER-002 Arch, PR body) to the sizes actually held. List the 10 response sizes and all command sizes as held to the table alone, and withdraw "the gate found" for GET_AUDIO_MAP.
- Verification: re-run `scripts/size_sweep.py`, `scripts/rom_size_probe.py` and the GET_AUDIO_MAP probe. Under (a), every listed probe fails by name. Under (b), the docs name exactly the passing set those scripts print.

### F2 - MINOR - the suites' `ucode.hex` rules do not list the table that is now a generator input

- Lenses: Tests, Robustness.
- Where: `tb/pp_top/Makefile:236` and `tb/ucpu/Makefile:20` (both `ucode.hex: .../gen_ucode.py` only); `hdl/aecp/ucode/gen_ucode.py:42-43` (now reads `aecp_commands.json`); disclosed at `docs/architecture/09_verification.md:501-503`.
- Evidence: `receipts/stale_prereq.log`, in a disposable copy. `make ucode.hex` built 518b900c...; the table was edited (STREAM_IS_RUNNING 12 -> 13); `make ucode.hex` then answered "'ucode.hex' is up to date" and kept 518b900c..., while a fresh generation gives 97151f6a.... No `tb/` mutation patch anchors on either Makefile line (searched every tracked `*.patch` and `*.diff` that names a Makefile, and every `ucode.hex:` rule).
- Authority: the PR's own change makes the table a build input of `ucode.hex`. The lane's purpose is that a table change cannot leave a consumer silently stale.
- Impact: after a table-only edit, an incremental local suite run grades a stale ROM and can pass or fail on old data. CI and the mutation drivers build fresh, so hosted results are not affected. Recording the defect does not remove it, and no technical blocker to the one-token fix was found.
- Required outcome, either of:
  - add the table to both prerequisite lists (and drop the "run make clean" workaround from 09 §8.10);
  - a maintainer-recorded public deferral with a tracked follow-up issue linked from 09 §8.10.
- Verification: in a copy, build `ucode.hex`, touch or edit only `aecp_commands.json`, and `make ucode.hex` regenerates.

### F3 - MINOR - the generated F06.14 doubles the plural of every per-record unit

- Lenses: Docs.
- Where: `scripts/check_aecp_commands.py:784` (`f", N {r['unit']}s"`) with units already plural in `hdl/aecp/ucode/aecp_commands.json` ("msrp mappings", "path entries", "mappings"). Output at `docs/architecture/06_aecp_engine.md:274, 275, 277, 278, 279`: "N msrp mappingss", "N path entriess", "N mappingss".
- Authority: `docs/README.md` §1/§3 (F06.14 is the normative command master table). The text sits in a generated artifact and its fix changes the generator or the table, so under the residue rule it is MINOR, not RESIDUE.
- Impact: every variable-size row of the normative table reads wrong, and `--write` re-emits it.
- Required outcome: drop the appended "s" in `resp_text` (or store singular units), run `--write`, and commit the regenerated rows.
- Verification: `grep -n "ss)" docs/architecture/06_aecp_engine.md` finds none in F06.14, and `make aecpcmd` passes.

### Suggestions (do not affect the verdict)

- S1 (Conformance, Tests): `STREAM_IS_RUNNING` has `"rtl": null` (`aecp_commands.json:23`), so the gate holds that code to nothing. A table-only 12 -> 13 passes the gate (`receipts/drifts.log` P4) and changes the ROM (97151f6a..., `receipts/stale_prereq.log`). Consider holding the Table 7-141 codes to a fixed list in the gate, or adding the RTL constant.
- S2 (Robustness): a `documented` row without `name` ends in a Python traceback with exit 1 (`receipts/drifts.log` P5), not a named schema line or an exit-2 refusal. `check_schema` could require each documented row's `opcode`, `name` and `cells`.
- S3 (Robustness): `gen_ucode.py:2443` stops generation with `assert`, which `python3 -O` removes. An explicit `raise SystemExit(...)` keeps the documented guarantee.
- S4 (Docs, parent export): the size-rule fields (`per`, `unit`, `plus`, `stub`, `echo`, `engine`, `max`, `engine_status`) are explained only by the gate's code. For the named parent consumer, describe them in the table's `about` or in 09 §8.10.
