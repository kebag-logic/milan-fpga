## Verdict

NEGATIVE. The command table, the generator wiring, the F06.14 generation, the CI wiring and the
byte identity all hold, and the gate does fail by name on every drift the lane names (re-applied
here independently: 5 of 5 lane drifts plus 3 more). But the gate's central size guarantee is
broader in the docs than in the code. 10 of the 31 served commands' response sizes, and every
command size, are held to nothing but the table. A ROM-only change to four variable-size programs
passes. The exact pre-PR F06.14 error for GET_AUDIO_MAP (32 + 8·N) also passes if it comes back
through the table. Meanwhile REQ-VER-002, 09 §8.10, the gate's docstring and the PR body all say
every response size is gated (F1, MAJOR). Two MINOR findings remain open as well: the suites'
`ucode.hex` rule does not list the new generator input (F2), and the generated F06.14 has a doubled
plural (F3). Acceptance items 1 to 3 are met. Item 4 is not met as written, because the Arch cell
records a size gate that does not exist for those rows. So "Closes #73" is not yet supportable.

- Lenses: Conformance, Tests, Docs.
- Where:

GET_AUDIO_MAP 32 + 8·N").
- Evidence. Each probe was applied to a fresh copy of the head export, with F06.14 regenerated by `--write` where the table changed:

The gate fails for 21 commands and passes for 10: ACQUIRE_ENTITY, READ_DESCRIPTOR, REGISTER_ and DEREGISTER_UNSOLICITED_NOTIFICATION, GET_AVB_INFO, GET_AS_PATH, GET_AUDIO_MAP, ADD_ and REMOVE_AUDIO_MAPPINGS, and GET_DYNAMIC_INFO.   - `receipts/rom_size_probe.log`: a ROM-only drift NOPs the first BUILD_FIELD or APPEND that E_RDESC, E_GAVB, E_GASP or E_GAMAP can reach. This is the same mutation the self-test uses for E_GSTRI. The gate passes all six; the same mutation on E_GSTRI and E_GCTRS fails by name.
- Authority: lane scope "A drift in any consumer (ROM data, engine constant or doc row) fails by name"; acceptance 1 (sizes in the table) and 4 (REQ-VER-002 Arch records what is gated); issue #73's own motivating defect (F06.14 sizes drifting from the engine).

Hold command cdl to the engine's decode floors, or record that it is held to nothing. Then add planted drifts for GET_AUDIO_MAP response cdl 20 and 28 (doc regenerated) and a NOPed header field in E_GAMAP, E_GAVB, E_GASP and E_RDESC, each failing by name.
  - (b) Narrow every claim (gate docstring, 09 §8.10 table and "still hand-written" paragraph, REQ-VER-002 Arch, PR body) to the sizes actually held. List the 10 response sizes and all command sizes as held to the table alone, and withdraw "the gate found" for GET_AUDIO_MAP.
- Verification: re-run `scripts/size_sweep.py`, `scripts/rom_size_probe.py` and the GET_AUDIO_MAP probe. Under (a), every listed probe fails by name. Under (b), the docs name exactly the passing set those scripts print.
