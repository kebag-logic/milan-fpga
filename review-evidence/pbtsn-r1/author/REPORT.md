## Architecture decision

tsn-c-stack has no AECP, AEM or SRP. The board runs milan-fpga's control firmware in milan-linux (A865's repo), with tsn-c-stack's ADP/ACMP/MAAP. I kept that design.

- The AEM is generated by the firmware builder from one YAML.
- tsn-c-stack gets the same model as `pbaem`, checked byte for byte, rather than a second runtime.
- Entity-behaviour changes to milan-linux went to A865 as patches, so the branch has one writer.

## Defects found and fixed

1. Adopted SR Domain VID not followed by the stream VLAN (bridge 0001).
2. SET_STREAM_FORMAT accepted only the default format; Milan 5.4.2.7/6.4 require every advertised base format (0001).
3. Every map edit refused; ES-4.16 would fail (0005, gated on mediad opting in).
4. Output STREAM_DEST_MAC_VALID set without a declaration, breaking REGISTERING flags (ES-12.6) (0006).
5a. GET_AVB_INFO without SRP_ENABLED (ES-4.13) and with a fixed class A mapping (ES-12.5) (0007).
5. CRF hard-coded as sink 1 in the far side and the media daemon (fixed in my snapshot; A865 rewrote it the same way).
6. main fails its own privacy gate (exempted on the branch, owner decision).

## Not a defect

The bridge's nvm suite failed after 20 power cuts with the new tsn-c-stack. Measured on both stacks, restart-to-settle runs 1.5-7.4 s against a 5 s window. The window is shorter than one re-advertise period plus the probe. Fixed in the test (0004).
