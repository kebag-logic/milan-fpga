## Root cause of #178

E_SCFG did compare the commanded index with the one in force and skip NOTIFY_ENQ on equality, but
the operands were in the wrong slots. The µCPU's COMPARE narrows only `ra` to the format (FMT_W,
16 bits) and takes `rb` whole (`KL_aecp_ucpu.sv` `b_or_imm_w` / `sub_w`). The index in force was in
`rb` (r6). Before the first SET the dynamic store is unset, and r6 is read from the image's ENTITY lane
at byte 304. That lane holds `configurations_count` (308..309) above `current_configuration` (310..311). With a
two-configuration bench image r6 is 0x0002_0000, so SET_CONFIGURATION(0) never compared equal and
always notified. On the single-configuration silicon image r6 is 0x0001_0000, the same bug. After a SET
the store value is clean, so the defect showed only on the image arm, which no check exercised. Fix:
`COMPARE ra=6, rb=12`. r6 is narrowed to the index, and r12 holds the index alone (`{48'd0, desc_ix_r}`,
`KL_aecp_engine.sv` opd2_w). Reproduced on the bench: the base ROM against the head bench fails NP1a
with "got 1 at the other controller and 0 at the requester", which is the issue's observation.

## Accepted lengths and refusal cases (SET_CONFIGURATION, opcode 0x0006)

Command: reserved @24, configuration_index @26, cdl 16 (IEEE 1722.1-2021 Figure 7-33). Every answer is
cdl 16 (a 28-octet AECPDU) and carries the CURRENT index (7.4.7.1): the dynamic store's once a SET has
written it, the image ENTITY's current_configuration before (0 if that locate misses).

| Order | Condition | Answer | Where |
|---|---|---|---|
| 1 | cdl 12..15 | BAD_ARGUMENTS, current index | engine dispatch -> E_SCFGBAD (unchanged) |
| 2 | any Stream Input bound or any Stream Output streaming | STREAM_IS_RUNNING, current index; ahead of the lock and the index | engine dispatch -> E_SCFGRUN (unchanged) |
| 3 | locked by another controller | ENTITY_LOCKED, current index | E_SCFG CHECK_LOCK -> E_SCFGLK (unchanged) |
| 4 | configuration_index >= configurations_count | **NO_SUCH_DESCRIPTOR**, current index; nothing stored, marked or notified | E_SCFG CHECK_ARG -> E_SCFGNSD (new, #179) |
| 5 | otherwise (cdl 16..100, the tb/aecp_cmds sweep) | SUCCESS echoing the index; store write and NVM mark | E_SCFG |
| 5a | ... index differs from the one in force | one unsolicited SET_CONFIGURATION to every registered controller but the requester | NOTIFY_ENQ |
| 5b | ... index equals the one in force | **no notification** | E_SCFG skip (fixed, #178) |

| configuration_index 0, descriptor_type CONFIGURATION, index 0, 1, 2, 0xFFFF (this bench image carries no CONFIGURATION descriptor) | NO_SUCH_DESCRIPTOR (2), 4-byte stub, cdl 20 (locate miss) |
| configuration_index 1 (< count), CONFIGURATION 1 | NO_SUCH_DESCRIPTOR, cdl 20 |

now gives. A configuration_index field past the count answers BAD_ARGUMENTS for every type, ENTITY and
CONFIGURATION included. IEEE 1722.1-2021 7.4.5.1 says that field "is ignored on receipt" for those two
types. That is a separate question for the owner, and it is not changed here.
