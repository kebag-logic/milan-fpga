## Known limitations / out of scope

- The ctrl gate's `rv32` arm does not build against the CI-pinned RV32 SDK (`ilp32d`, no
  `gnu/stubs-ilp32.h` for `-mabi=ilp32`). This is pre-existing: it fails the same way at base
  `423ac5d9`. `firmware-unit` runs the ctrl gate before installing the SDK, so the arm reports
  SKIPPED by name; the store's RV32 arm runs hosted with `--require-rv32`. Fixing the ctrl arm is an
  F0 decision, tracked in #679.
- lwSRP is a private repository, so `firmware-unit` cannot run the opt-in `lwsrp` arm; the coverage
  ratchet reads the same with and without it. lwSRP's own upstream suites run with lane F4.
- The planted-defect campaigns stay local gates (minutes at 16 jobs, too long for a 4-vCPU fast job),
  and so do the tally listener's planted defects (`tally_selftest.py --mutants`).
- Tallies now count tests, not assertions; the per-arm split and merge is stated in the harness README
  and every check is mapped by its words in the lane's handoff.
- Hosted evidence: `rtl-fast` run 37445962183 at `e7e0c10f` passed, including `firmware-unit`, at
  the 2026-10-06 11:07:55 UTC snapshot (round 1: run 37429204550 at `27433e47`). The round-3 head has
  no hosted run, and the act replay is the manager's. At the round-3 head the job's `run:` steps were
  replayed verbatim in an `ubuntu:24.04` container (GoogleTest 1.14.0, gcc 13.3.0) and passed, with the same coverage table as gcc 16 and every exclusion matching. That is
  a replay, not hosted or act evidence.
- `rtl-full` at `27433e47` was red on `Verilator shard 2/5`: `milan_dp_mclk` hit its 1800 s wall
  clock and was refused as `NOCOUNT`, as at the base `423ac5d9` (dev's push run 37412878143); #673
  tracks it. At `e7e0c10f` that shard passed. This PR changes no RTL and no bench.
- Found while testing, not changed here (firmware behaviour), tracked in #677: `nvm_klj2_record`
  reads an erased record's payload past `loaded` when the record's header ends exactly at `loaded`.
  The verdict is right and the store's own calls cannot reach it, but a caller holding only the
  bytes `nvm_klj2.h` asks for gets an out-of-bounds read (AddressSanitizer: `nvm_klj2.c:298`).
  `codec_loaded_prefix` leaves that one case out, and its comment says so and cites #677.
- The five `adp.c` coverage exclusions rest on the rule #678 rules (ports never call back into the
  core synchronously), which `adp.h` does not state until #678's F0 follow-up lands; the harness
  README says so and does not claim the standard met without it. A port that breaks the rule
  reaches every item the rows name: a send port calling `adp_link_change` from inside a send reaches
  rows 1 and 2, a timer port expiring a timer from inside `timer_start` reaches rows 3 and 4, and a
  link port calling back twice from inside `adp_set_enable(true)` reaches row 5. The adapter in the
  tree keeps the rule.
