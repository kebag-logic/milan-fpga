## Description

The retained SoC crossings change storage form only. Their control (LiteX's
gray-code pointers, two-stage synchronizers and compares) is untouched, and so
are widths, depths, throughput, read latency, clock domains and resets.

| Array | Before | After |
|---|---|---|
| `mac_tx_cdc`, `mac_rx_cdc` (16 x 74) | 1 RAMB36 + 1 RAMB18 each: the 72-bit payload fills the RAMB36, LiteX's `first`/`last` spill into a RAMB18 | payload in 1 RAMB36; `last` in 1 RAM32X1D (`first` is unread and trimmed) |
| CSR W (4 x 38) | 5 RAM32M + 2 RAM32X1D + 32 FF | 1 RAMB18 (the array and its read register) |
| CSR R (4 x 36) | 6 RAM32M + 32 FF | 1 RAMB18 |
| CSR AW, AR | 3 RAM32M + 14 FF each | unchanged |
| CSR B | trimmed | unchanged |

The two RAMB18s the MAC crossings free are the two the CSR W and R FIFOs
take, so RAMB36 and RAMB18 counts are unchanged (the gate allows no growth).

Code:

- `sw/litex/milan_soc.py`: `_crossing_storage` reaches the one storage array of
  a LiteX `stream.ClockDomainCrossing` and refuses any other shape;
  `_payload_in_block_ram` replaces it with a block-RAM payload array and a
  distributed-RAM framing array on the same write address/enable and read
  address. `MilanMAC` applies it to both MAC crossings; `_cross_csr_bus` (the
  CSR crossing `add_milan_datapath` built inline) applies it to W and R.
  `_mac_cdc_rename` names the existing paired shadow-domain map. `_axis_dp_cdc`
  is unchanged, so the excluded `descmem_*`/`respmem_*`/`nvmmem_*` crossings
  are untouched.
- `sw/litex/gen_mac_tx_model.py` mirrors the product call; the converted chain
  under `tb/verilator/gptp_txts/generated/` is regenerated by the generator.
- `sw/litex/test_retained_cdc_storage.py` (new, in the LiteX simulation
  aggregate): all seven arrays, built by the product code, in lockstep with
  stock LiteX crossings; named checks `storage`, `lockstep`, `order`, `depth`,
  `reset`; five planted-defect controls.
- Docs: `docs/litex/CLOCK_DOMAINS.md` (crossing map and storage note),
  `docs/testing/TESTING.md`, `docs/design/MARK_II_AREA_PLAN.md` (M2
  intermediate measurement), `docs/design/AREA_BUDGET.md`.

Measured through the M0s recipe (Vivado 2026.1, same flow identity as the
record, one run at a time under the host lock):

| | LUT | FF | Slices | RAMB36 / RAMB18 | WNS / WHS, ns |
|---|---:|---:|---:|---:|---|
| Base route, dev `e8454e27` | 50,267 | 54,413 | 15,779 | 74 / 27 | +0.299 / +0.031 |
| M2 route, `4177835c` | 50,139 | 54,354 | 15,771 | 74 / 27 | +0.306 / +0.019 |
| Routed delta | -128 | -59 | -8 | 0 / 0 | +0.007 / -0.012 |
| Post-synthesis delta (same runs) | -34 | -61 | - | 0 / 0 | - |

- The base route equals the `route-1x1` record in every gated figure. The M2
  route passes the gate (`check` rc 0): 0 failing setup, hold or pulse-width
  endpoints, no negative-slack path in any of the four signoff corners, every
  net routed. The constraints and shipping Tcl are identical to base apart
  from checkout paths; no timing exception was added.
- Attribution: the changed arrays lose 11 RAM32M (44 LUTRAM sites) and keep
  RAM32X1D level (W -2, MAC framing +2). Post-synthesis the netlist also gains
  10 logic LUTs in the CPU's AXI-Lite bridge, giving -34 LUT. The further
  routed logic movement (-86, mostly the protocol-processor wrapper, -42) lies
  in untouched RTL; it is not credited as a saving.
- Against the plan's 200 LUT (100-400) estimate: the reproducible saving is
  34 LUT, below the range. The arrays' whole LUTRAM footprint was 72 sites.
  BRAM: no extra tile (the plan allowed up to two).

  range. The cumulative ledger tables keep the planning figure; the week-4
  re-measure reprices them.

  LUTs and 28 FFs more for +2 RAMB18 (one tile), within the plan's two-tile
  allowance but a zero-growth gate failure.

  primitive and stays as it is.

  between the 1x1 and 8x8 exports, at base and at this head; the builder gate
  elaborates both shapes.
- No re-record: the Mark II exception (D7) keeps the gate record until M9.
- `tx_sf`, LiteDRAM queues, `memory_port_cdc*`, CPU bridges, `descmem_*`,
  `respmem_*`, `nvmmem_*`, mailbox rings and media/gPTP tables are untouched.
