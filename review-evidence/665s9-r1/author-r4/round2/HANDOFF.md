## Design decision (evidence first)

Round 1's routed `ExtraTimingOpt` checkpoint, re-timed (`receipts/r2/ana/summary.txt`): the worst `reg_rdata_r`
path that does not pass the bound-talker read-back was itself +0.022 ns (18 levels, bit 24), under the floor. So
registering the read-back alone could not close it, and the whole register read multiplexer left the bus's cycle:

- every register read is decoded from an offset registered at its request (`rd_off_r`), through its own copy of the
  bound-talker, publication and face decodes, and answered two mailbox clocks after the request;
- ring reads (receive rings, event ring) and every write keep one (their data is the block RAM's own registered port);
- the bound-talker read-back memory is read the cycle after the request, at an address `KL_mbx_rx` registers then;
- GM_LO's GM_HI/DOMAIN snapshot is taken in the cycle the multiplexer samples GM_LO, so the pair stays one identity.

Added cycles per access, mailbox clock (100 MHz in the split): register read +1 (2 after the request instead of 1);
ring read 0; write 0. Measured: S2's harness's `host_cycles` reads min 1 / max 2 (`receipts/r2/gates/budget-1x1.log`;
fixture group 5,870 accesses, 8,829 cycles), where the committed fixture recorded 1 / 1. The adapters wait for the
answer already (Wishbone B4 and AXI4-Lite let it come any cycle later), so they are unchanged.
