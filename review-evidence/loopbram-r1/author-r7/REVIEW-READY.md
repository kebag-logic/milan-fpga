sources, `sw/firmware/ctrl/aecp/{aecp,aecp_commands,aecp_maps,aecp_image,aecp_state}.c`, with the host `cc` into `libaecp.a`.

compiles read. So it compiles the firmware: it is not `OUTSIDE`.

`{python} tb/verilator/input_loopback_dp/run.py --shape S --work {work}/input-loopback-S --build-only` for S = 1 and 8.
It needs Verilator (`needs="verilator"`), so `firmware-verilator` (`--only verilator`) judges it, and `firmware-boundary` and both
capture legs (`--without verilator`) leave it out and name it. The new LEGS layout is unaffected: a builder the run leaves out is in no leg.
The `BUILDERS` comment and the firmware README's builder list now say four Verilator builders.

**The non-dp suite, checked the same way** ([log](receipts/boundary--logs--loopback-found-by-text.log.txt)). The gate's own
discovery (`ctrl_configs.candidates()` and `builder()`) finds six files under the two suites. Only `input_loopback_dp/run.py`
names the firmware's tree. `input_loopback/{Makefile,bounds.py,mutants.py}` and `input_loopback_dp/{Makefile,mutants.py}`
