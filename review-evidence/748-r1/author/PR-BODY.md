## Description

**Cause.** act mounts one volume, the tool cache at `/opt/hostedtoolcache`, into every job container of a replay. Each job's `HOME`, `RUNNER_TEMP` (`/tmp`) and workspace are its own. `actions/setup-python` resolves the elaboration interpreter from that cache, and the LiteX install, the VexiiRiscv clone and submodule update, the cached CPU metadata copy, the patch series and the Scala generation all write into that interpreter's site-packages. Two `elaborate` legs started together therefore clone into one directory and contend for one git lock, and reverse each other's patches: the two failed #745 replays.

**Fix (the assignment's first option).** The `elaborate` template gains one setup step after setup-python:

```sh
set -euo pipefail
python3 -m venv "$RUNNER_TEMP/litex-venv"
echo "$RUNNER_TEMP/litex-venv/bin" >> "$GITHUB_PATH"
```

Every later step's `python3` is then the job's own venv, so it installs, fetches and patches only there; the tool cache is only read. No other step's text changes.

In the #739 replay and in both failed #745 replays, which ran jobs of all four workflows, every log line naming the cache's Python belongs to `elaborate-gates-0` or `-1`.

**Cache keys.** No key formula and no template cache `path` changed. Every key that hashes `.github/workflows/*.yml` (pip downloads, Scala, CPU metadata, Verilator, sv2v, exact Python downloads, apt) takes a new value at this head and misses once, as on any workflow edit; the RV32 SDK key does not and still hits. The generated apt cache's `path` moves from `ci_packages_16` to `ci_packages_17` with the step index, which changes that entry's version too; its key already misses once.

**Wall clock against #737.** On hosted runners each job already had its own runner, so the added cost is the venv step: 2.3 to 2.4 s per leg (three native runs, both legs). #737's projections of 1475 s and 1353 s of 1620 s become about 1478 s and 1356 s. Under act, a leg no longer finds the other leg's VexiiRiscv checkout or Scala output in the shared tree, so each leg places its own (12 to 14 s) and runs its own generation, as hosted. Natively, both legs run concurrently in their own venvs with cold Scala caches: leg 0's gate step took 987 s and leg 1's 452 s; the #739 replay's were 919 s and 484 s. Setup per leg is about 50 s (venv 2.3 s, install 32 to 35 s, placement 12 to 14 s, patches 0.4 s).

## Known limitations / out of scope
