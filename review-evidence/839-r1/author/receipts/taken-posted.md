Authoritative references: IEEE 802.1AC-2016 11.1 (source_address is the individual address of the source MSAP), IEEE 802.1Q-2022 6.8.1 (EISS source_address as defined for the ISS), IEEE 802.3-2022 2.3.1.2 (the MAC entity inserts its own address), Milan v1.2 4.2.7; issue #839 acceptance 1 to 4
Interpreted scope: fix it in the datapath, which holds every transmitter. The station-MAC CSR pair records when each half has first been written since reset. Until both have been, the frame start of each of the five sources (the protocol processor's SRP/ADP/ACMP/AECP lane, MAAP, the gPTP plane, the AAF talkers, the CRF talker) is held at that source, so no frame starts and no arbiter watchdog sees a refused beat. At the MAC boundary, octets 6 to 11 of every frame are taken from that CSR, so a frame the processor built into its slot before the write cannot leave with a stale address. The firmware boot order and the register map's addresses and fields stay unchanged. The CSR change is the pair's own sequencing only, documented on the MAC_ADDR rows. No new top-level port, no submodule edit.
Validation plan: a new milan_dp leg boots the shipping 1x1 shape from reset through configure_fabric()'s ordered writes, read from the compiled firmware, then the restore walk and the entity enable. It checks the source address of every frame at the MAC boundary up to and past the first ENTITY_AVAILABLE. Planted mutants (no hold, no stamp, both removed, one half enough) must each fail it by name.
